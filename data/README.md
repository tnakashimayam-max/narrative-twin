## 選ぶ版の物語の作り方

物語は、人が読み合わせた台本（`data/select/script_YYYY.jsonl`、書き方は [docs/script-format.md](../docs/script-format.md)）を、`fiction/run_script.py` で本物の AI に流して作りました。流した結果の数字は [docs/tools.md](../docs/tools.md) の「10年分の物語を流した結果」にあります。

2036-05-05 の節目の控えから、次の命令で表ごとの JSON に書き出しました。

```
python -m fiction.story_data export 控えのデータベース
```

データベースはリポジトリに入れません。新しいクローンで `python -m app` を起動すると、最初の1回だけ `data/select` を読み込み、写真を `data/photos/` へ写します。AI は呼ばないので、API キーがなくても開きます。費用の記録（`ai_calls`）と、どの版を選んだかの記録は入れていません。

前の物語（`eval/previous_story/`）は、基本の RAG と比べたときの土台です。デモでは使いません。

## 流したあとで当てた直し

全部を流し直さず、流し終えたデータに次の7つを当てました（記録の文の直しは `fiction/record_fixes.py`、ほかの6つは `fiction/story_fixes.py`）。セルフの盤面とやり取りの読みは、`python -m fiction.selfhood_replay` で10年分を再生して作りました（再生 r4。`selfhood_pieces_*.json` 3,017行、`selfhood_evidence_*.json` 6,286行、`selfhood_documents.json` 12行、`dialogue_readings_*.json` 3,854行、$10.10）。解釈（`interpretations_*.json` 4,655行）は、言明ごとに AI の読みを1つ持つ形です。作り方と検証は `docs/verification/selfhood/` にあります。心の目次は別に、`python -m fiction.heart_reread` で作りました（`tables/heart_readings.json`、659行、$1.19）。`data/select`、`2036年の場面` と `2026年の場面` の控え、架空用のデータベースに、同じ内容を当てています（セルフ、やり取りの読み、心の目次は、`2036年の場面` の控えと架空用のデータベースにも入れた）。流した元の控え（`data/trial/new_story/run_select/`）は変えていません。

| 直し | 内容 | AI |
|---|---|---|
| 今日の一言 | 一言がある817件を今の決まりで判断し、重い話と判断した374件の一言の行を部屋の行から外した。受け止めの文は残す。発言の台帳の行も残す | Haiku 5.5、$0.314 |
| 家系図の関係 | 誠一さんと和子さん（夫婦）、2人と美穂さん（親子）、美穂さんと健太くん（親子）の4行を足した。`2026年の場面` には足していない | 使わない |
| 話に出てきた人の候補 | 人ではない語（井ノ口内科、小雪、亀、おる）と、登録済みの人（健太、先生、たなか）の7件を「ちがう」にした | 使わない |
| 井ノ口先生の立場 | 流したときの「縁のある人・かかりつけ医」を「専門職・主治医」にした。言明の札は「縁のある人の証言」のまま | 使わない |
| 読んだ位置 | 人ごとに、ほかの人の発言の最後の3件だけを未読に残した。流した物語では誰も部屋を開いていないので、入れないと10年分がすべて未読に数えられる | 使わない |
| 井ノ口先生に託す | 田中さんを招いた日（2036年1月18日）に、本人が主治医にも託した。託す設定の行を1行足した。`2026年の場面` には足していない | 使わない |
| 記録の文の直し | 田中さんの2036年5月2日の今の様子「蓋は、誠一さんが開けました。」を、1文で分かる文に直した行として1行足した（`fiction/record_fixes.py`）。元の行は履歴に残る。`2026年の場面` にはこの記録がない | 使わない |

```
python -m fiction.record_fixes tables
python -m fiction.record_fixes db データベース
python -m fiction.story_fixes judge 判断に使うデータベース
```

台本（`data/select/script_YYYY.jsonl`）は流したときのままです。理由と確かめた結果は [docs/decisions.md](../docs/decisions.md) の「流したあとで当てた直し」にあります。

## script.jsonl から記録を作る

決まりは [docs/script-format.md](../docs/script-format.md)、道具は `fiction/run_script.py` です。今ある API を順に呼ぶので、記録は画面から入れたものと同じ処理を通ります。結果は `--folder` の下に入り、`data/narrative_twin.db` には触れません。

```
python -m fiction.run_script script.jsonl --check
python -m fiction.run_script script.jsonl --folder data/trial/script_run --budget 10
```

試しのファイルは `fiction/sample_script.jsonl`（24行）です。1回流すと約 $0.10 かかります（固める処理を含みます）。

チャットの行は、本物のツインの返事を見ずに書いたものです。流すと、ツインの返事は本物の AI が書きます。ツインの問いに本人の答えが要る場面では、AI が本人の短い受け答えを足します。**AI が足した文は画面の会話にだけ出て、本人の言葉として記録されません。** 言明にならないので、田中さんにも届きません。チャットの行は一字も変えません。

AI の推測のうち、推測01（「庭のある暮らしそのものを大切にされているのかもしれません。」）だけは台本の文です。本物の AI の推測が庭の話にならなかったときだけ入ります。どちらになったかは、流した `--folder` の `correction_scene.json` に残ります（[docs/script-format.md](../docs/script-format.md) の「訂正の場面」）。

## 2036年と2026年の場面を開く

新しい物語を流した選ぶ版を、`python -m app`（8000番）で開きます。流した元のデータは変えず、写しを `data/trial/snapshots/` に置いています。

| 控えの名前 | 日付 | 開く場面 |
|---|---|---|
| `2036年の場面` | 2036-05-06 | ケア会議の日。田中さんが入れる |
| `2026年の場面` | 2026-11-03 | 訂正の場面の前。花びらは白い |

開き方。動いているサーバーの下でファイルを入れ替えると壊れるので、必ず止めてから戻します。

```
（8000番のサーバーを Ctrl+C で止める）
python -m fiction.snapshot restore --from 2026年の場面
python -m app
```

2036年へ戻すときは、`--from 2036年の場面` にします。同じ命令で何度でも行き来できます。

- 戻す前のデータベースと写真は消さず、`data/trial/replaced/` へ移します。1回あたり最大約180MB 増えるので、撮り終えたら手で片付けます。
- **撮影中に入れた言葉は、もう一方の控えへ持ち越されません。** 戻すと、控えの時点のデータになります。
- 日付はデータから決まります。最後に固めた日の翌日で、最初の起動で決めた日を覚えるので、起動し直しても動きません。
- 記録が入っているデータベースに、物語は重ねません。
- `python -m fiction.snapshot list` で控えの一覧を出せます。

## 触ったあとで元へ戻す

画面で入れた言葉を撮影と公開のデータに混ぜないよう、触る前に控えを取り、触ったあとで戻します。

```
（8000番のサーバーを Ctrl+C で止める）
python -m fiction.snapshot save
python -m app
```

戻すときは、サーバーを止めて `python -m fiction.snapshot list` で名前を確かめ、`python -m fiction.snapshot restore --from 控えの名前` を流します。`data/select/` は画面の操作では変わりません。

## デモの写真

投稿の写真は、AI（Codex の image_gen）で作った架空の写真を使います。文章の指示だけで作り、実在の写真を参考にしません。開くデータが使う分だけを `data/select_photos/` に入れて Git に入れます。元の写真の置き場（`data/demo_photos/`）と `data/photos/` は Git に入れません。人の顔、文字、看板、ロゴ、表札は写しません（将棋の駒の字を除く）。Git に入れません。プロフィールの7人の顔は、別の扱いです（下の「プロフィールの顔」）。

1. 元の写真をリポジトリの外のフォルダに置きます。ファイル名は写真の番号にします（例：`P20261001-1.jpg`）。形式は JPEG、PNG、WEBP です。
2. 写っているものを人の目で確かめます。プログラムでは確かめられません。
   - 人の顔や姿（窓やガラスに映ったものも含む）
   - 看板、表札、住所、郵便物、車の番号、建物の名前
   - 手書きの文字、画面に映った内容、事業所の掲示
3. 撮影の情報を消します。

   ```
   .venv/Scripts/python -m fiction.prepare_photos 元の写真のフォルダ
   ```

   撮影の位置、日時、カメラの情報、コメントを消し、長い辺を1568px以下にした JPEG を `data/demo_photos/` に出力します。書き出したあとに開き直し、情報が残っていないことを確かめます。読めない写真と、確かめに通らない写真は出力しません。

4. 出力した写真を開き、向きと写っているものをもう一度確かめます。アプリには、出力した写真だけを入れます。

## プロフィールの顔

7人の顔は、AI（Codex の image_gen）で文章の指示だけから作った架空の人物です。作った日は2026年11月4日です。実在の人や写真を元にしていません。顔も `data/select_photos/` に入れて Git に入れます（アイコンとプロフィール写真で14枚）。人の目で確かめ、リポジトリには入れません。

整え方は上の「デモの写真」と同じで、出力先だけが違います。

```
.venv/Scripts/python -m fiction.prepare_photos 元の写真のフォルダ --output data/demo_photos/profile
```

ファイルと人の対応は `fiction/faces.py` にあります。

| ファイル | 人 | 入るとき |
|---|---|---|
| `01_seiichi.jpg` | 誠一さん | 起動のとき |
| `02_miho.jpg` | 美穂さん | 起動のとき |
| `03_kenta.jpg` | 健太くん | 登録したとき |
| `04_masao.jpg` | 正雄さん | 起動のとき |
| `05_setsuko.jpg` | 節子さん | 起動のとき |
| `06_inokuchi.jpg` | 井ノ口先生 | 登録したとき |
| `07_tanaka.jpg` | 田中さん | 招いたとき |

- 1枚を、その人のアイコンとプロフィール写真の両方に入れます。写真の行とファイルは枠ごとに分けます。
- 入れるのは架空用の起動と、`fiction.run_script` の `--folder` のデータベースだけです。自分用の起動には、同じ名前の人がいても入れません。
- 新しいデータベースでは、最初の控え（`first-start`）より前に入れます。控えにも顔が入ります。
- 空いた枠にだけ入れます。入れ替えた写真は、起動し直しても上書きしません。
- 人は登録の名前か呼ばれ方で引きます。表の名前と同じでなければ入りません。
- `data/demo_photos/profile/` がなければ何も入れず、頭文字の丸のまま動きます。
