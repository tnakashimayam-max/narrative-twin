# 登場人物とチャットの設計（11/3）

デモの登場人物を6人にし、それぞれがログインしてチャットでき、グループにツインが入れるようにする設計です。未読、既読、部屋から出る操作も作ります。人物はすべて架空です。

## 目的

今の作りには次の不足があります。

- 架空の人物が4人で、妻と友人がいない
- 部屋を作れるのは本人だけで、必ず本人が入る
- ケアマネジャーが最初からいて、10年後に現れる形になっていない
- ツインをグループに入れられるのは本人だけ
- 部屋から人をはずす操作がない
- 新しい発言に気づきにくく、読まれたかも分からない

## 決めたこと

| 項目 | 決めたこと |
|---|---|
| 部屋を作る | 全員ができる。作った人は必ず入る。本人がいない部屋もできる |
| 本人がいない部屋 | 本文を AI に送らず、言明にしない。本人には見えない |
| ケアマネジャーの登場 | 2036年以降の日付で、本人か、立場が家族の託された人（美穂さん）が招く。招いたあと日付を2036年より前に戻すと、ログイン一覧と相手の一覧から消える。架空用だけの決まり |
| ツインを入れる、はずす | 本人と、立場が家族の託された人ができる。本人がいる部屋だけ。部屋に表示する |
| 部屋から人をはずす | グループを作った人と、部屋にいる本人ができる。本人はほかの人にはずされない |
| 自分で部屋を出る | グループなら全員ができる。本人が出たらツインも一緒にはずれる |
| 未読 | 1対1とグループの一覧に数を出す。部屋の中に「ここから新しい発言」の線を出す |
| 既読 | 自分の発言に、1対1は「既読」、グループは「既読 2人」のように出す。名前は出さない |
| 通知 | 作らない |
| タイムライン | 変えない。いいねの数、既読、通知を作らない |
| ケア会議の部屋 | 誠一さん、美穂さん、田中さんで新しくグループを作る。作ったあとの部屋に人を足す操作は作らない |

## 操作できる人の決め方

招く操作とツインの操作は、次の関数1つで決めます。

```python
def can_act_for_self(conn, viewer) -> bool:
    """本人か、立場が家族の託された人かを返す。"""
```

招かれた専門職にも `delegations` の行が入るので、行の有無だけでは決めません。専門職が次の専門職を招いたり、ツインをはずしたりしないよう、立場が家族であることも確かめます。縁のある人も通しません。

## 招く

新しい道 `POST /api/people/professional` を作ります。

- **できる人：** `can_act_for_self` が真の人。それ以外には、道がないのと同じ 404 を返します。
- **入力：** 名前、呼ばれ方、続柄。立場は専門職に固定します。
- **処理：** 人の登録と託す設定の追加を、1つの処理で行います。
- 託された人が登録できるのは専門職だけです。家族や縁のある人の登録は、今までどおり本人だけです。
- 招かれた人に見えるのは、本人が「意思決定支援用」にした記録だけです。招いた人が見える範囲を広げることはできません（原則10）。

### 日付との組み合わせ（架空用だけ）

切り替えの日付は `config` に1か所で持ちます（2036年1月1日）。今の日付は `clock.now` で読みます。

| 今の日付 | 招く道 | 専門職のログイン | ログイン一覧と相手の一覧 |
|---|---|---|---|
| 切り替えの日付より前 | 404 | できない（401） | 出ない |
| 切り替えの日付以降 | 使える | できる | 出る |

自分用の起動では、日付で切り替えません。自分用は日付を動かせないためです。

## 部屋

### 作る

`POST /api/rooms` を、ログイン中の全員が使えるようにします。

- 作った人を必ず部屋の人に入れます。
- 作った人は、`room_members` の部屋ごとの最初の行です。作るときに作った人を先頭で入れているので、新しい列はいりません。
- 1対1の部屋を探すときは、2人とも入っている部屋を探します。今は本人が必ず入る前提で相手だけを見ているので、直します。
- 部屋の相手を選ぶために、新しい道 `GET /api/people/choices` を作ります。ログインできる人の番号、名前、呼ばれ方、立場、写真の番号だけを返します。生まれた年やメモは返しません。`GET /api/people` は本人だけのままです。

### はずす、出る

| 道 | できる人 | 動き |
|---|---|---|
| `POST /api/rooms/{room_id}/members/{user_id}/remove` | そのグループを作った人と、部屋にいる本人 | 本人ははずせない。部屋に表示する |
| `POST /api/rooms/{room_id}/leave` | そのグループにいる人 | 部屋に表示する |

- 対象はグループだけです。1対1とツインとの部屋には使えません。
- 部屋の人でない人と、操作できない人には 404 を返します。
- はずれた人と出た人は、部屋の発言も写真も開けなくなります。発言は記録として残ります。
- 本人が出たら、ツインも同じ処理ではずします。ツインの会話を閉じ、はずれたことを部屋に表示し、新しい発言を裏で言明に分けます。
- 足し直す操作はありません。もう一度話すときは新しい部屋を作ります。

### ツイン

`POST /api/rooms/{room_id}/twin` を次のように変えます。

- **できる人：** その部屋にいる人のうち、`can_act_for_self` が真の人。それ以外の人には 404 を返します。
- 本人がいない部屋には入れません（400）。
- 入れたことと、はずしたことを、今までどおり部屋に表示します。

本人が入っている部屋だけなので、ツインは本人がいない部屋の本文を読みません。部屋の情報には、この操作ができるかを `can_manage_twin` で返し、画面はそれを見てボタンを出します。

## 未読と既読

新しい表 `room_reads(room_id, user_id, last_read_seq)` に、人ごとの読んだ位置を持ちます。既存の表は変えません。

| 道 | 動き |
|---|---|
| `POST /api/rooms/{room_id}/read` | 画面が部屋を開いて発言を出したときに、読んだ位置を進める。戻さない |
| `GET /api/rooms` | 部屋ごとに `unread_count` を返す |
| `GET /api/rooms/{room_id}/messages` | 最初の未読の位置と、ほかの人の読んだ位置の配列を返す。名前は返さない |

- 3秒ごとの読み込みでは読んだことにしません。画面が開いていて見えているときだけ、画面が送ります。
- 未読の数には、自分の発言とお知らせの行を入れません。
- 既読の数には、部屋にいるほかの人だけを入れます。はずれた人とツインは入れません。
- ツインとの部屋では、未読の数と既読を出しません。AI が読んだことを「既読」と言わないためです。
- 読んだ位置は、部屋の人だけに返します。AI には渡しません。言明にも開発のログにも入れません。

## この設計に入れないもの

| もの | 扱い |
|---|---|
| 物語と10年分の架空ログ | 物語を決めてから、別の設計で作る。写真も含むので、作成の道具はこのリポジトリの外に置く |
| 10年後のケアマネジャーとツインのチャット、ケア会議 | 10年分の架空ログを元にするので、最後に仕上げる |
| 作ったあとの部屋に人を足す操作、後から入った人の見える範囲 | 作らない。ケア会議は新しいグループで見せられるため |
| 通知、タイムラインの既読 | 作らない |

## 残る限界

| 限界 | 受け止め |
|---|---|
| 既読があると、読んだことが相手に伝わり、返事を急かされることがある | 名前を出さず、トークの部屋だけに限る。タイムラインと通知には広げない |
| 託された人が招くと、本人が決めた範囲の記録が田中さんに見える | 田中さんを招いたことは人の一覧に出る。本人は人の管理から、はずすことができる |
| パスワードのない簡易ログインなので、だれでも一覧のだれにでもなれる | 今の決まりのまま。サーバーは 127.0.0.1 だけで待ち受ける |
