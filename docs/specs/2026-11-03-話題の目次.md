# 話題の目次の設計（11/3）

本人とツインの会話で、発言と写真に問いを仮置きし、話題ごとに記録を結びつけ、何年前の話でも今の話とつなげて深掘りできるようにする設計です。例はすべて架空です。

## 目的

今のツインは、今の会話、新しい10会話の要約、新しい40件の本人の言葉を読みます。そのため次のことができません。

- 古い話を、今の話と結びつける
- 同じ話題の繰り返しに気づく
- 前に立てた問いと答えを、話題の単位で積み上げる

質問のたびに似た文を探す RAG とベクトル検索は使いません（CLAUDE.md の方式と「作らないもの」）。話題の目次に積み上げ、読む量を一定に保ちます。

## 会話の例

```
（7年前）誠一さん：つつじ公園に桜を見に行きました。
          → 話題「つつじ公園」「桜」、探す語「花見」、判別「明るいかふだんの話」を記録

（今日）  誠一さん：［公園の写真］
          ツイン：桜の咲いた公園ですね。この公園はどこの公園ですか？
          誠一さん：つつじ公園です
          ツイン：つつじ公園なのですね。
          ツイン：7年前にもつつじ公園には花見に行きましたね。変わっていましたか？
```

## 決めたこと

| 項目 | 決めたこと |
|---|---|
| 問いの頻度 | 2回に1回を基本にし、聞く回は発言が短いときを優先する |
| 前の話を持ち出す場面 | 今の発言に関係があるときだけ。期間の上限は置かない |
| 作り方 | 話題の目次（NAK の視点別目次のうち、本人の視点の目次にあたる） |
| 写真 | 写真を先に読む呼び出しは分けない。問いを立て、本人の答えで話題に結びつける |
| 過去の言い方 | 本人の発言の記録がある事実は言い切ってよい |
| つらい記憶 | メッセージごとに明暗を判別して記録し、持ち出す記録を限る |
| 話題と判別を作る時期 | 発言ごとの分を、会話を閉じたときにまとめて作る。問いの仮置きだけは発言ごと |
| 話題に結びついた問いを断ったとき | その話題だけを休ませる。休んだ話題はホームの一覧から戻せる |
| 過去を持ち出す回 | 問いを書く回だけ。問いには「この話はお休みにする」が付くので、本人が止められる |

## 第1段：問いの頻度と仮置き

### 問いの頻度

AI を呼ぶ前に、プログラムが「この回は問いを書く／書かない」を決め、入力に入れます。

| 今の発言 | 問いを書いてよい条件 |
|---|---|
| 短い（30字以下。写真だけの発言を含む） | 問いの連続が2回未満 |
| 長い（31字以上） | 受け止めだけの回が2回続いたあと |

- 字数の値は `config` に1か所で持ちます。
- 問いを書かない回に AI が問いを返したら、プログラムが落とします。
- 体や命、強いつらさの場面と、本人が終えたそうなときの判定は、今のまま優先します。
- 受け止めだけの回の数は、`memory.questions_in_a_row` と同じ形で数えます。
- プロンプトの「毎回は問いません。目安は2回に1回です」は、入力の指定に従う文に置き換えます。

### 問いの仮置き

`TwinTurn` と `TwinPhotoTurn` に、仮置きの問いを受け取る項目（問いとテーマの組、2個まで）を足します。

- 返事と同じ呼び出しで受け取ります。呼び出しは増えません。
- 型では止めません。多ければ先頭の2個に切り、不備のある問いは捨てて数えます。1つの不備で返事全体をやり直さないためです。
- 問いが1つであること、`question_is_allowed` を通ることをプログラムが確かめます。読めないテーマの問いは捨てます。
- 保存の形は2種類です。広げる問い（「どんな駒を使っていますか？」）と、推測を確かめる問い（「将棋がお好きなのかもしれません。合っていますか？」）です。推測は確かめる形に限ります。
- 保存先は `question_logs` の未使用の行（`asked_on IS NULL`）です。候補の選び方、使用済みの印、結果を、今の処理のまま使います。

## 第2段：話題の目次

### 表

既存の表は変えず、新しい表だけを足します。自分用のデータベースは、再起動で表が増えるだけです。

| 表 | 中身 |
|---|---|
| `topic_index` | 語、話題の名前、別名か、出どころの印、発言の番号、写真の番号、会話の番号、日付 |
| `question_links` | 問いの番号と、話題の名前か写真の番号の結びつき |
| `message_tones` | 発言か写真の番号、明暗の判別、モデル名、作った時刻 |
| `topic_marks` | 会話ごとの処理済みの印（`room_messages` の rowid） |

- `topic_index` は本文を持ちません。原文は `utterances` から番号で取り出します。
- 話題と判別は、発言と写真の説明から作り直せる AI の読み取りです。追記だけの台帳にはしません。印を戻して流し直すと作り直せます。
- 問いと答えの結びつきは保存しません。問いの次の本人の発言と `question_logs.result` から求めます。

`topic_index` の出どころの印は3種類です。

| 印 | 発言の番号 | 写真の番号 | 意味 |
|---|---|---|---|
| 発言に語が出た | あり | なし | 本人の発言に語が文字として出た |
| 問いへの答え | あり | 問いが写真についてなら あり | 問いへの本人の答えで結びついた |
| 写真の AI の読み取り | なし | あり | 写真の説明に語が出た。本人は確かめていない |

### 問いと答えの結びつけ

問いの次の本人の発言を、次の条件をすべて満たすときに答えとして扱います。

- AI の読み取り `previous_question_result` が「答えた」か「途中」
- 問いと同じ会話
- 発言の原文がある（写真だけの発言は答えにしない）
- `detect_care` が「なし」で、`says_goodbye` でない

これで「はい、好きです」のように語が出ない答えも、話題に結びつきます。AI の判断ではなく、プログラムの決まった手順で結びつけます。

### 話題の整理

会話を閉じたあと、`jobs.after_close` の処理として、役割「話題の整理」の AI を会話ごとに呼びます。

- **入力：** 番号を振った会話の行（本人の発言、ツインの問い、写真の説明）
- **出力：** 行ごとの明暗の判別、話題の名前、別名
- **モデル：** Haiku 5.5 で始めます。架空のデータで Sonnet 5.5 と比べ、結果を `docs/tools.md` に残します。
- **対象：** ツインとの部屋の会話だけです。グループ、スレッド、人だけの部屋は入れません（原則14、15）。
- **長い会話：** 言明への分割と同じ上限で、数回に分けて処理します。
- **失敗：** `jobs._guarded` で `job_failures` に残し、`catch_up` が起動のときに流し直します。これで既存の会話も取り込みます。

プログラムが次のことを確かめます。

| 対象 | 確かめ |
|---|---|
| 話題の名前 | その行の発言か写真の説明に文字として出ている。2文字以上 |
| 別名 | 2文字以上。探すためだけに使い、ツインの入力にも画面にも出さない |
| 名前と別名の両方 | `_NOT_TO_ASK` の語と語の頭を含まない |
| 既存の話題との統合 | 新しい名前が既存の別名と一致、または新しい別名が既存の名前と一致したら、同じ話題にする |
| 体や命の言葉のある行 | 話題に入れず、判別は「つらさを含む」にする |
| 判別がない行 | 「分からない」で埋める |

### 明暗の判別

値は「明るいかふだんの話」「つらさを含む」「分からない」の3つで、確からしさは持ちません。

- 「ふだんの話」を入れるのは、日常の話題まで止めないためです。
- 明暗が混ざる思い出は「つらさを含む」にします。
- これはメッセージに付けた仮説で、本人の内面の断定ではありません。NAK-4V の「気持ち」とは単位と目的が違うので、「思い出の明暗の仮説」と呼びます。
- 画面に出さず、ツインの入力にも書かず、自分用の開発のログにも書きません。持ち出さない行を省くだけに使います。ツインが「つらい思い出でしたね」と言う材料を渡さないためです。

### 目次の引き方

ツインの返事の前に、問いを書く回だけ、プログラムが話題を引きます。

```sql
SELECT canonical_term, MIN(spoken_on), MAX(spoken_on), COUNT(*)
FROM topic_index
WHERE instr(:text, term) > 0
GROUP BY canonical_term
```

- `:text` は今の発言と、今の会話の写真の説明です。
- 名前か別名が文字として出た話題だけを引きます。最近の話題で埋めることはしません。
- 期間では絞りません。
- 当たった語が長い順、同じなら初出が古い順に、10話題、3,000字まで渡します（`config.MEMORY_LIMITS`）。
- 今の会話の記録は渡しません。今の会話の全文は別に読んでいるためです。

各話題で渡すものは次のとおりです。

```
- つつじ公園（初めて 2019年4月3日・7年前／最近 2024年5月1日・2年前）
  本人の言葉（2019年4月3日）：「つつじ公園に桜を見に行きました。」
  写真の AI の読み取り（2024年5月1日）：桜の木の下に…
  未使用の問い：どの季節によく行きますか？
```

- 本人の言葉は、初出と最新の原文を1件ずつ、文の切れ目で切って渡します。
- 年数の言葉は、プログラムが日付から作ります。1年以上は「N年前」、1か月以上は「Nか月前」、それ以外は「N日前」です。
- 未使用の問いは、話題ごとに2件までです。

### 持ち出さない記録

プログラムが、渡す前に行か話題を省きます。

| 条件 | 省くもの |
|---|---|
| 判別が「明るいかふだんの話」でない | その行 |
| 同じ話題のどこかに「つらさを含む」がある | その話題 |
| 本文に亡くなった人の名前、呼び方、続柄がある（登録した人と候補の両方。今の発言にその人が出ていれば除く） | その行 |
| テーマ「つらかったこと」の言明の本文に話題の名前がある | その話題 |
| 本文に `_NOT_TO_ASK` の語か語の頭がある | その行 |
| 今の会話の本人の発言に、体や命の言葉か `_NOT_TO_ASK` の語がある | その会話の目次全体 |
| 話題が休んでいる | その話題（本人が触れても渡さない） |
| この会話で、話題を使った問いが2回に達した | その会話の残りの目次全体 |

### 過去の言い方

`TwinTurn` に `topic_used` を足します。渡した話題の名前と一致するときだけ受け取り、問いと話題を `question_links` に結びます。

過去に触れる文（年数、日付、「去年」「昨年」「おととし」「先月」「先週」「前回」「以前」「前にも」を含む文）を、プログラムが確かめます。

| 確かめ | 通る | 落とす |
|---|---|---|
| 年数と日付 | 渡した言葉にある | 渡していない年数。日付のない過去の言い方での言い切り |
| 出どころ | その日付に本人の発言の行がある | 写真の読み取りか要約の行しかない。ただし「かもしれません」「うかがった気がします」、問いの形なら通す |
| 話題の名前 | 使った話題の名前が文にある（別名は数えない） | 名前がない |
| 「」の引用 | 本人の発言の原文と一字一句同じ（`words_are_real`） | 原文にない |

- 問いの文で確かめに通らなければ、問い全体を落とします。返事の文なら、その文を落とします。直そうとはしません。
- 問いが落ちた回は、過去に触れる文も落とします。
- 目次で渡した本人の発言の本文を、`words_are_real` の `sources` に足します。写真の説明の行は足しません。
- プロンプトの「前の日に聞いた言葉」の決まりを、この形に書き換えます。
- 変えるのは本人とツインの部屋だけです。`thread_system`、`group_system`、`reports_self` は変えません。

### 話題のお休み

- 話題に結びついた問いを本人が断ったら、テーマではなく、その話題だけを休ませます。
- 休んでいる話題は `question_links` と `question_logs.result` から求めます。
- 話題に結びついていない問いは、今までどおりテーマで休みます。
- ホームのお休みの一覧に話題も出し、戻せるようにします（`app/rooms.py`、`static/home.js`、`docs/api.md`）。

### 候補の問いの選び方

`memory._pending_candidates` の順を、次のように変えます。全体の上限は今の5件のままです。

1. 今の発言に当たった話題に結びついた問い（話題ごとに2件まで）
2. 今の会話の写真に結びついた問い
3. 残りを新しい順

### 開発のログ

- 役割「話題の整理」を `config` の3つの辞書と `devlog` の操作の一覧に足します。
- 結果の言葉に「過去の言い切りを落とした」を足します。
- 自分用のログには、話題の名前、別名、判別、問いを書きません。

## 残る限界

| 限界 | 受け止め |
|---|---|
| 本人が話していない変化（その後に亡くなった同行者など）はプログラムに分からず、本人が聞かされることがある | 本人の次の言葉と「この話はお休みにする」で話題を休ませる |
| 日付と話題が合っていても、言い換えた中身が正しいかは確かめられない | 本人のその場の訂正が次の発言として記録に残る |
| 作ったときに想定しなかった言い方は当たらない | 固有名詞は文字どおり出るので、結びつきの大半はそこで取れる |
| 判別を誤ることがある | 迷ったら「分からない」で持ち出さない。Sonnet 5.5 と比べて測る |

## 作らないもの

- 話題、別名、判別を見せる画面
- 話題を返す API（お休みの一覧を除く）
- 固める処理、家族や専門職の視点の目次、固定化警告
- 分割の AI に写真の説明を渡すこと
- 画面に回数や連続日数を出すこと（原則7、13）

## 原則との対応

| 原則 | この設計での扱い |
|---|---|
| 3 出どころ | 話題と判別は AI の読み取り。入力の行に「本人の言葉」「写真の AI の読み取り」のラベルを付ける |
| 4 推測 | 推測は「合っていますか？」の形でだけ聞く |
| 6 話さない自由 | 持ち出さない記録の表と、話題のお休み |
| 7、13 引き留めない | 回数と連続日数を画面に出さない |
| 9 本人の言葉 | 本人とツインの部屋で、ツインが思い出す形に限って言い切りを認める。日付と話題の名前を必須にする。本人の言葉を伝える「」の引用は一字も変えない。本人以外には言い切らない |
| 10 範囲 | 目次は本人とツインの部屋でだけ使う |
| 14、15 招かれた部屋 | 目次を作る元はツインとの部屋の会話だけ。グループとスレッドのツインには渡さない |
