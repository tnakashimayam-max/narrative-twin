# script.jsonl の決まり

架空の10年分を、今あるアプリの道（API）へ順に流すためのファイルの決まりです。流す道具は `fiction/run_script.py` です。

人物と記録はすべて架空です。**ツインの文はファイルに書きません。** ツインは流したときに本物の AI が答えます。

## ファイルの形

- 文字コードは UTF-8、1行に1件の JSON です。空の行は書きません。
- 時刻の順に並べます。同じ時刻なら、書いた順に流します。
- 名前は `誠一さん` のように、さんを付けて書きます。

全部の行に共通する項目は次の3つです。

| 項目 | 内容 |
|---|---|
| `at` | `"2026-04-12T08:10"` の形の日時 |
| `kind` | 行の種類（次の表） |
| `by` | その操作をする人 |

**時刻について：** 流す時刻は `at` のとおりになり、画面に出る時刻も `at` になります（`POST /api/dev/date` の `at`）。同じ時刻の行は、書いた順に1秒ずつずらします。発言の順番を時刻に残すためです。`at` が前の行より前だと流せません。

## 行の種類

| `kind` | すること | `by` | 書く項目 |
|---|---|---|---|
| `発言` | 部屋で話す | 部屋にいる人 | `room`、`text` か `answer`（写真だけなら `photo`）。任意で `photo`、`topic` |
| `閉じる` | ツインとの部屋で「今日はここまで」 | 誠一さん | `room`（`ツイン`） |
| `便り` | その日の話を便りにする | 誠一さん | `ref`、`body`、`share_with`。任意で `photo` |
| `コメント` | 便りにコメントする | 便りを見られる人 | `letter`（便りの `ref`）、`text` |
| `今の様子` | 今の様子を入れる | 託された家族か専門職 | `text`。任意で `theme`、`at_meeting` |
| `確かめ` | 本人が記録に答える | 誠一さん | `match`。任意で `reply` |
| `訂正` | 本人が記録を直す | 誠一さん | `match`、`text` |
| `本人だけにする` | その発言の記録を「今は話したくない」にする | 誠一さん | `text` |
| `推測` | 台本の文を、AIの推測として足す | 誠一さん | `text`、`match`。任意で `theme` |
| `人` | 人を直す、足す | 誠一さん | `name` と、直す項目 |
| `託す` | 託す人とテーマを決める | 誠一さん | `delegates`、`themes` |
| `招く` | ケアマネジャーを招く | 誠一さんか、託された家族 | `name`、`relation` |
| `部屋` | 人の部屋を作る | 部屋に入る人 | `room`、`room_kind`、`members` |
| `ツインを入れる` | グループにツインを入れる、はずす | 誠一さんか、託された家族 | `room`、`present` |
| `受け答え` | ツインの問いに本人の短い受け答えを足す | 誠一さん | `hint`。`room` か `letter`。任意で `limit`、`twin_replies` |
| `整理` | 固める処理を流す（「記録を整理する」） | 誠一さん | なし |
| `段階` | 人生の段階を切り替える | 誠一さん | `stage` |

### 発言

```json
{"at":"2026-04-12T08:10","kind":"発言","room":"ツイン","by":"誠一さん","text":"今朝も縁側でお茶を飲みました。","topic":"縁側の朝"}
```

- `room`：`ツイン` は本人とツインの部屋です。それ以外は `部屋` の行で付けた名前です。
- `text`：書いた文を一字も変えずに送ります。
- `topic`：その日の会話の題です。任意で、書き出すログの `trigger` に使います。省くと最初の発言の冒頭を使います。
- `photo`：`data/demo_photos/` の中のファイル名です。
- `text` も `answer` も書かず、`photo` だけの発言もできます。

```json
{"at":"2026-04-12T08:15","kind":"発言","room":"ツイン","by":"誠一さん","photo":"庭.jpg"}
```

### 本人がツインに答える番

ツインの問いは流してみるまで分かりません。`text` の代わりに `answer` を書きます。

```json
{"at":"2026-04-12T08:12","kind":"発言","room":"ツイン","by":"誠一さん","answer":{"hint":"庭は妻と手入れしてきたので、今も毎朝見ると話す","must":"毎朝この庭を見るのが楽しみなんです。"}}
```

| 項目 | 内容 |
|---|---|
| `hint` | 答えの筋。AI が、ツインの実際の問いを見て、この筋で答えます |
| `must` | 必ず言う言葉。文字列か、文字列の配列です。**一字も変えません。** |

- `hint` と `must` のどちらかは必ず書きます。
- `must` は、句点（`。`）、`！`、`？` で終わる文にします。記録に入るのは文の切れ目で始まり終わる言葉だけなので、文の途中までの言葉は本人の言葉として残りません。
- AI は `must` の前と後の文だけを書き、`must` はプログラムが間に入れます。AI に書き写させないので、一字も変わりません。同じ文にはつなげません。つなげると、前の言葉が付いたまま本人の言葉になるためです。
- 会話の最初の行は `answer` にできません。ツインがまだ話していないためです。
- ツインは2回に1回ほどしか問いません。問いがないときも、AI はツインの受け止めの文を見て、筋に沿って話を続けます。

AI の前の文が文の切れ目で終わっていないときは、もう1回作らせます。それでもだめなら、`must` の文だけを送ります。`must` がなく `hint` だけの行で作れなければ、そこで止まります。

### 本人の短い受け答えと、問わない日

チャットは本物のツインの返事を見ずに書いたので、ツインが問うても次の行は答えになりません。そこで次の2つを使います（`python -m fiction.convert_chat --answers` が入れます。決まりは `fiction/answer_plan.py`）。

```json
{"at":"2026-10-11T08:10","kind":"発言","room":"ツイン","by":"誠一さん","text":"飯は炊きたてが一番たい。"}
{"at":"2026-10-11T08:10","kind":"受け答え","by":"誠一さん","room":"ツイン","hint":"この日の事実と話し方の例","limit":25,"twin_replies":true}
{"at":"2026-10-12T08:10","kind":"発言","room":"ツイン","by":"誠一さん","text":"雨たい。","ask":false}
```

| 項目 | 内容 |
|---|---|
| `ask` | `false` なら、その行ではツインが問いません。`発言`、`コメント` に書きます。省くと問えます |
| `受け答え` の `room` か `letter` | ツインとの部屋か、便り（`ref`）に足します |
| `hint` | 渡す事実と話し方の例です。未来ログとその日のチャットから作ります。病名の文と本人のいない部屋の話は入れません |
| `limit` | 字数の上限です |
| `twin_replies` | `true` なら、受け答えのあとにツインが受け止めて返します（問いは出しません） |

- **問いが出ていなければ何も足しません。**
- AI が書いた文は、字数、病名、泊まりの語、関西の言い方、一人称、丁寧語、事実にない数字をプログラムで確かめ、新しい人、出来事、数字がないか、筑後弁かを別の AI で確かめます。通らなければ書き直させ、3回でだめなら決まった短い言葉にします（`fiction/added_words.py`）。
- **足した文は本人の言葉として記録しません。** ツインとの部屋では部屋の行にだけ入れるので、発言の表に入らず、言明、要約、人の候補になりません。ツインの次の返事にだけ渡します。便りではコメントに出ますが、分割の印を足した文の後ろへ進めるので言明になりません。書き出すログの本人の発言にも入れず、`extra_YYYY.json` に `足した文` として書きます。
- チャットの行は一字も変えず、足した文とは別の吹き出しで流します。

時期ごとの決まり：

| 時期 | 足す文 | ツインの問い |
|---|---|---|
| 2032-09 まで | 25字まで | 対象の日に問う |
| 2032-10〜2034-09 | 短文（12字まで） | 対象の日に問う |
| 2034-10〜2035-09 | 途切れた短い言葉（8字まで） | 対象の日に問う |
| 2035-10 から | 足さない | 問わない |

対象の日は、動画の期間（2026-10-01〜11-03、2036-01-18〜05-06）、決まった言葉の日、田中さんの引用の日、`ツインへ` の日です。それ以外の日は、ツインは受け止めるだけで問いません。コメントのあとの問いは、動画の期間、決まった言葉の日、引用の日の、最初に人がコメントしたときだけです。グループではツインは問いません。

### 閉じる、便り、コメント

```json
{"at":"2026-09-28T09:00","kind":"閉じる","room":"ツイン","by":"誠一さん"}
{"at":"2026-09-28T09:05","kind":"便り","by":"誠一さん","ref":"将棋の便り","body":"将棋の会で一手ずつ考えるのが好きだと話しました。","share_with":"縁のある人まで"}
{"at":"2026-09-28T18:00","kind":"コメント","by":"正雄さん","letter":"将棋の便り","text":"また一局お願いしたいですね。"}
```

- ツインとの部屋は、日付が変わる前に必ず `閉じる` を書きます。
- ツインとの部屋の会話は、1日に1回までです。書き出すログが日付ごとに1回の形だからです。
- `便り` は、同じ日にツインとの部屋の会話がある日に出します。`閉じる` より前でも出せます。閉じたあとの便りはその日の会話を指し、閉じる前の便りはどの会話も指しません（「便りの下書き」の道は使わないので、本文の書き方は変わりません）。
- `share_with` は `家族` か `縁のある人まで` です。`ref` はファイルの中だけの名前で、`コメント` の `letter` から指します。
- `便り` の `body` は人が確かめた便りの本文です。今の道（下書きを AI が作る）は使いません。

### 確かめと訂正

```json
{"at":"2026-04-12T08:20","kind":"確かめ","by":"誠一さん","match":"毎朝この庭を見るのが楽しみなんです"}
{"at":"2026-11-03T08:20","kind":"訂正","by":"誠一さん","match":"庭が好きなのかもしれません","text":"庭より、和子と暮らしてきた場所だから大切なんです。"}
```

- `match`：記録の本文に含まれる言葉です。言明の番号は乱数なので、文で指します。**まだ確かめていない記録を先に、その中で新しい記録から探します。**
- `reply`：`そうです`（省いたとき）か `今は話したくない` です。
- 記録の本文は、会話を閉じたあとに AI が分けて作ります。そのため、`確かめ` と `訂正` は `閉じる` のあとに書きます。`match` は、`text` や `must` に書いた文か、その一部にします。
- 合う記録が見つからないと、そこで止まります（`--keep-going` を付けると、書き残して続けます）。

### 本人だけにする

```json
{"at":"2026-04-12T08:21","kind":"本人だけにする","by":"誠一さん","text":"和子の話は、今はしたくありません。"}
```

その発言からできた、本人が確かめられる記録（本人の言葉と AI の推測）を全部「今は話したくない」にします。画面の「今は話したくない」と同じ道（`POST /api/statements/{番号}/rest`）を通ります。

- `text`：発言の文です。発言の全体と同じものがあれば、それだけを指します。なければ、文を含む発言を指します（`must` に書いた文で指せます）。
- 指すのは、この行の日までで、いちばん新しくその文を話した日の発言です。**同じ日のほかの発言の記録は休ませません。**
- `閉じる` のあとに書きます。記録は閉じたあとにできるためです。
- その発言がまだ言明に分かれていなければ止まります。あとから分かれた記録が休まないまま残らないようにするためです（`--keep-going` を付けると、書き残して続けます）。
- 続きから流しても、休ませた記録に行は足しません。

### 推測

```json
{"at":"2026-04-12T08:22","kind":"推測","by":"誠一さん","match":"毎朝この庭を見る","text":"庭に思い出があるのかもしれません。"}
```

本人の発言のうち `match` を含むものを根拠に、出どころ「AIの推測」の言明を足します。**この行は台本の文で AI の出力ではありません。** AI は呼びません。

- `match`：この行の日までで、いちばん新しくその言葉を話した本人の発言を根拠にします。見つからないと止まります（`--keep-going` を付けると、書き残して続けます）。
- `text`：すべての文を「かもしれません」「でしょうか」など言い切らない形で終わらせます。言い切る文は `--check` で止まります。「合っていますか？」は本文に入れません。
- `theme`：任意です。省くと、同じ発言の記録のテーマに合わせます。記録がなければ `大切にしてきたこと` にします。
- 範囲は `本人だけ`、状態は `未確認` で入ります。あとの `確かめ` の行で、本人が答えられます。
- 続きから流しても、同じ発言を根拠にした同じ文は足しません。

### 今の様子

```json
{"at":"2036-04-26T17:00","kind":"今の様子","by":"美穂さん","text":"歩くときは手を添えると安心した顔になります。"}
```

`theme` を省くと `住まい・土地` になります。`at_meeting` を `true` にすると、会議の画面から入れた扱いになります。

### 段階

```json
{"at":"2033-05-01T00:00","kind":"段階","by":"誠一さん","stage":"要支援"}
```

人生の段階を切り替えます。`stage` は `元気な時期`、`要支援`、`要介護` です。その日から後の会話は、この段階を引き継ぎます。画面に道がないので、道具の中で部屋のない会話を1行足します。発言がないので、これまでの記録の一覧に空の日は出ません。続きから流しても重なりません。

最初の会話より前の年には書きません。ツインの成長の絵は、いちばん古い会話の年から始まり、人生の段階の期間も会話の日付から求めるためです。

### 人、託す、招く、部屋

```json
{"at":"2026-04-01T00:00","kind":"人","by":"誠一さん","name":"和子さん","relation":"妻","birth_year":1954,"residence":null,"is_deceased":true}
{"at":"2026-04-01T00:01","kind":"人","by":"誠一さん","name":"美穂さん","relation":"長女","residence":"遠く"}
{"at":"2026-04-01T00:02","kind":"部屋","by":"誠一さん","room":"将棋の部屋","room_kind":"グループ","members":["正雄さん"]}
{"at":"2026-04-01T00:03","kind":"託す","by":"誠一さん","delegates":["美穂さん"],"themes":["家族","住まい・土地"]}
{"at":"2036-04-01T10:00","kind":"招く","by":"美穂さん","name":"田中さん","relation":"ケアマネジャー"}
```

- 新しいデータベースには、誠一さん、和子さん、美穂さん、正雄さん、節子さんが最初から入っています。**ファイルの最初に `人` の行を書いて、新しい設定に直します。** 和子さんには `is_deceased` を付けます。付けるとログインできなくなり、話し手にできません。今は「同居」になっているので、`residence` を `null` にします。残すと、家系図に同居の囲みが出ます。
- `人` の項目は、`called_name`、`role`、`relation`、`residence`（同居／近く／遠く）、`birth_year`、`gender`（男性／女性／不明）、`is_deceased`、`memo` です。まだいない名前なら、足します。
- **健太くんは `人` の行で登録すると話し手にできます。** `role` を `家族` などにして、話す行より前に書きます。登録するとログインできる人になり、入口に出ます。登録しないあいだは話し手にできません。
- `themes` の値は、家族、仕事・役割、住まい・土地、好きなこと、大切にしてきたこと、人の手を借りること、つらかったこと です。
- `招く` は2036年1月1日以降だけです。田中さんはそれより前には話し手にできません。
- `部屋` の `room_kind` は `1対1` か `グループ` です。`members` に作る人を含めなくても、作る人は入ります。`room` はファイルの中で部屋を指す名前で、そのまま部屋の名前になります。

## 書いてはいけないこと

`--check` が次の言葉を探します。`text`、`hint`、`must`、`body`、`topic`、`memo` のすべてが対象です。

- **病名と診断：** 脳出血、脳梗塞、脳卒中、麻痺、高次脳機能障害、誤嚥、肺炎、認知症、アルツハイマー、パーキンソン、糖尿病、高血圧、癌、腫瘍、骨折、診断、病名。ほかに、漢字の語が「症」「炎」「病」で終わるもの（例：後遺症、心臓病。看病は除きます）。
- **泊まりとショートステイの話：** 泊まり、泊まる、ショートステイ、ショート、短期入所、宿泊。

物語の設定として知っていても、発言と記録には書きません。ツインは健康や病気の判断をしないので、記録にも病名を入れません。泊まりの話は、ケアマネジャーが聞いたときに「まだ聞けていません」と答える場面に使います。

**例外：ツインのいない部屋の `発言` でだけ、「認知症」「アルツハイマー」「診断」を書けます。** 「アルツハイマー型認知症」のように、これらの言葉で終わる語も通します。人だけの部屋の本文は AI に渡らず、記録にもならないためです。

- ほかの病名と、泊まりの語は、ツインのいない部屋でも書けません。
- ツインのいる部屋、ツインとの部屋、`発言` のほかの行の種類では書けません。
- その部屋にツインが入っている間は書けません。はずしたあとは書けます。

次の言葉は書けますが、`--check` が知らせます。ツインが決まった文とつなぎ先を返し、会話がそこで止まるためです（`app/twin.py`）。

- 倒れた、胸が痛、胸が苦し、息が苦し、意識が、ろれつ、血を吐、急に動けな、激しい痛 など
- 死にたい、消えたい、自殺、生きている意味、いなくなりたい、もう耐えられない、もう限界 など

体や薬のことを「どうしたらいいかな」「やめていいかな」と聞く発言には、ツインは問いを返さず、相談先の文を添えます。こちらは `--check` では知らせません。

## 決まった言葉のファイル

別に渡す決まった言葉は、次の形の JSONL にします。`--check --fixed ファイル` で、`date` の日の行に一字も違わず入っているかを確かめます。

```json
{"date":"2026-04-12","by":"誠一さん","text":"毎朝この庭を見るのが楽しみなんです。","room":"ツイン"}
```

- `by` と `room` は任意です。書くと、話し手と部屋も確かめます。
- `text`、`must`、`body` の中に含まれていれば合格です。`hint` の中だけにあるものは合格にしません。`本人だけにする` と `推測` の `text` も、本人が話した文ではないので合格にしません。

## 流し方

```
python -m fiction.run_script script.jsonl --check                 # API も AI も呼ばず、ファイルだけを点検する
python -m fiction.run_script script.jsonl --check --fixed 決まった言葉.jsonl
python -m fiction.run_script script.jsonl --folder data/trial/script_run --budget 10 --workers 4
```

- 流し込みは `--folder` の下の新しいデータベースで行います。`data/narrative_twin.db` と `data/story/` には触れません。
- サーバーは立てません。画面が使うのと同じ API を、同じプロセスの中のアプリへ送ります。8000番にも8001番にも接続しません。
- 流す前に点検を通します。問題があると流しません。
- 使った費用は `--budget`（ドル）を超えそうになると止まります。省くと5ドルです。確かめるのは20行ごとと `整理` の前なので、超え方は数行分の費用までです。
- 途中で止まったら、同じ命令をもう一度流すと続きから進みます。プロセスが落ちたときも同じです。
- `--until 2026-11-02` を付けると、その日までで止まります。

結果は `--folder` の下の `story/` に、`data/story/` のログと同じ形（`log_YYYY.json`）で書き出します。ログの形に入らないもの（人の部屋の発言、今の様子、確かめ、訂正、本人だけにする、推測、段階）は `extra_YYYY.json` に書きます。

## 裏の処理を待たずに進める（--workers）

AI を待つ時間の多くは、言明への分割と人の候補です。これを裏に回して、次の行へ進みます。

| 分け方 | 処理 | 理由 |
|---|---|---|
| 本線で待つ | ツインの返事、「今日はここまで」、会話の要約、グループのツイン | 次の発言や次の日の会話が読むため |
| 裏に回す | 会話を閉じたあとの言明への分割と人の候補、コメントのあとのスレッドの問いと言明への分割 | あとから動いても、結果が変わらないため |

`--workers N` は同時の数の上限です。省くと2です。`0` にすると、裏の処理も順に待ちます（前の動きと同じです）。

- **同時の数：** 2本から始めて、問題がなければ5分ごとに1本ずつ、N まで上げます。429 か 529 が返ったら半分にし（最低1本）、また少しずつ上げます。急に増やすと API が断ることがあるためです。
- **全部終わるまで待つ行：** `確かめ`、`訂正`、`本人だけにする`、`推測`、`整理`、`段階` の前と、`託す`、`人`、`招く` の前です。記録を探す行と、裏の処理が読むものを変える行です。流し終わるときと、`--stop-after` や `--until` で止まるときも待ちます。
- **日付：** 裏の処理が日付の切り替えのあとに動いても、記録の日付は会話の日のままです。
- **スレッドの順番：** 同じ便りの処理は順に動かします。次のコメントの前に、前のコメントの処理が終わるのを待ちます。ツインの問いが次のコメントの後ろに入らないようにするためです。
- **待ちの上限：** 待ちと動いている処理の合計が、その時点の本数の8倍を超えたら本線が待ちます。ツインの記憶の遅れを数日分以内にするためです。
- **一時の失敗：** 429、503、529、接続の失敗などは、`retry-after` があればその秒数、なければ5秒から倍々で最大60秒待ってやり直します。待っている間は、本線も含めて全体で新しく AI を呼びません（呼んでいる途中の1回は止めません）。何度やってもだめなら止まります。発言は欠けず、同じ命令の続きで全部入ります。
- **待っても直らない失敗：** 400、401 などと API キーがないときは、すぐに止まります。`retry-after` が15分より長いときも、待たずに止まります。
- **続きから流す：** 待ちの中の処理が失われても、印（`split_marks`）を見て、未処理の分だけを流し直します。全部の会話を AI に送り直しません。

### 数字のファイル（jobs_stats.json）

同時の数を決める材料を、流す間に `--folder` の下の `jobs_stats.json` に書きます。本文は書きません。続きから流すと足していきます。`--workers 0` では作りません。

| 項目 | 内容 |
|---|---|
| `workers_limit` | `--workers` の値 |
| `workers_now` | その時点の本数 |
| `workers_lowered` | 本数を半分にした回数 |
| `queue_max` | 待ちの長さの最大 |
| `queue_wait_seconds` | 待ちがいっぱいで本線が待った秒数の合計 |
| `barrier_wait_seconds` | 全部終わるまで待つ行で本線が待った秒数の合計 |
| `rate_limited` | 429 と 529 の回数 |
| `other_transient` | ほかの一時の失敗の回数 |
| `waited_seconds` | 全体で待った秒数の合計 |
| `write_waits` | 書き込みの鍵を0.05秒以上待った回数（`ledger.atomic` の分） |
| `write_wait_seconds` | 書き込みの鍵を待った秒数の合計（`ledger.atomic` の分） |
| `lock_failures` | データベースのロックの失敗の回数 |
| `job_seconds` | 裏の処理の秒数の合計 |
| `jobs_done` | 終わった裏の処理の数 |
