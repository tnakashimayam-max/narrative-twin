# モデルと機能の表

目的を決めてから選びます。目的がないものは使いません。期待どおりに役立たなければ外し、理由をここに残します。

値段とモデル名は、公式の料金表（`platform.claude.com/docs/en/about-claude/pricing`）で 2026-11-02 に確かめました。

| モデル | 入力（1M トークン） | 出力（1M トークン） | バッチの入力 | バッチの出力 |
|---|---|---|---|---|
| `claude-opus-5-5` | $4 | $20 | $2 | $10 |
| `claude-sonnet-5-5` | $2 | $10 | $1 | $5 |
| `claude-haiku-5-5`（プロンプトが10万トークン以下） | $0.10 | $0.50 | $0.05 | $0.25 |
| `claude-haiku-5-5`（プロンプトが10万トークンを超える） | $0.50 | $2.50 | $0.25 | $1.25 |

Haiku 5.5 の扱いは、公式の説明で確かめて次のようにしています（`app/ai.py`）。

- サーバー側の代替（fallbacks）がないので送りません。断られた応答（`stop_reason` が `refusal`）は、やり直さず、ほかの失敗と同じメッセージで扱います。
- 考える処理が最初から有効で、応答の先頭が thinking のことがあります。本文は位置ではなく種類で選びます。
- 考える処理の分は `max_tokens` に含まれます。上限を小さくしすぎると本文の前で切れるので、余裕を持たせています。

共通の機能：

| 機能 | 目的 | 選ばなかった案 |
|---|---|---|
| JSON 出力と Pydantic での検証。だめなら1回やり直す | 決めた型に合うものだけを受け取るため | SDK の `parse`：断られた応答が読み取りの失敗になり、断られたことが分からない |
| 拒否の代替（`fallbacks: "default"`） | 安全の確認で断られても、API の側で別のモデルに切り替えるため。Opus と Sonnet だけで使う | なし。切り替わる場面は、通信を差し替えたテストでだけ確認 |

処理ごとの分担です。アプリの機能として動いている処理を書きます。未作成の役割は、作ったときに足します。

| 処理 | Claude が担うこと | プログラムが確かめること | 本人が決めること | 決まった手順だけでは足りない理由 |

## 重い言葉の分割でモデルを選ぶ（11/4）

発言の中身をプログラムが判断し、必要なときだけモデルを Sonnet 5.5 へ選択する（`app/twin_model.py` の `reason_to_split_deep`、`app/intake.py` の `split_and_save`）。

本人の言葉は作り直せない。上の比べで Haiku 5.5 は発言を1つ落とし、言い切りの文を作った。回数の多い短い話は Haiku 5.5 で足りる。同じ3単位の比べで Sonnet 5.5 は費用が約12倍（$0.0059 と $0.0683）、時間は短くなった（39.0秒と23.2秒）。全部を Sonnet 5.5 にせず、本人が長く話した回と、人生、体、気持ちの語がある回だけにする。

| 決まり | 内容 |
|---|---|
| 対象 | ツインとの部屋の会話（場所が「日記と会話」）の分割だけ。スレッドのコメントとグループは Haiku 5.5 のまま |
| 見る発言 | その回に分ける本人の発言。ツインの発言、ほかの人の発言、文脈として渡すだけの前の発言は見ない |
| 選ぶとき | どれか1つの発言が80字以上か、`reason_before_answer` の理由が体や命の場面、体の話、人生に関わる話、気持ちの話のとき |
| 選ばないとき | 相談の語だけの発言。「？」だけで選ばないため |
| 本文のやり直し | 答えたモデルと同じモデルで行う |
| 答えられないとき | 断られた、型に合う答えが出ない、API に届かないときは Haiku 5.5 の答えを使う。何も残らないより良いため。Haiku 5.5 も答えられなければ言明を入れず、印を進めず、次の処理で流し直す |
| 呼ぶ回数の上限 | Claude の呼び出しは最悪6回、通信の失敗の繰り返しを含む HTTP の要求は最悪18回 |
| 記録 | `ai_calls` とログに、実際の役割とモデルを残す |

| 選ばなかった案 | 理由 |
|---|---|
| 全部 Haiku 5.5 | 落とした発言と言い切りの差が、作り直せない重い回にも残る |
| 全部 Sonnet 5.5 | 費用が約12倍。回数の多い短い話は Haiku 5.5 で足りる |
| AI に判断させる | 毎回の費用と待ち時間が増え、判断もぶれる |

見込み：物語のチャット全件で約770回、1回あたり約 $0.023 で約 $18。流して確かめた数字ではない。回数は、本人のつぶやき、ツインへの話、本人だけの記録を1日ごとにまとめて `reason_to_split_deep` に通すと、3,081日のうち766日が選ばれることから出した。1回あたりの費用は見込みで、実測ではない。

本人の発言が言明にならなかった割合は、2026-10 から2036年までの試しで、Sonnet 5.5 が131件のうち6件、Haiku 5.5 が797件のうち1件だった。Sonnet 5.5 の分に重い言葉が集まるので、そのままの比べにはならない。本人の発言が言明にならなければ1回やり直す（`docs/decisions.md`）。

この形で Sonnet 5.5 と Haiku 5.5 の差を測ってはいない。上の比べはプロンプトに決まりを足す前の3単位だけで、重い回で差が大きいと確かめたものではない。バッチで分割する道具（`fiction/generate.py`、`scripts/trial_log.py`）はこの判断を通らず、Haiku 5.5 のまま。

試して見つけたこと：

- Haiku 5.5 は、体の相談の場面を足した最初の版で、「最近、膝が痛い」「眠れない」に119番の案内を付けた。急な不調だけに当てはめるとプロンプトに書くと膝の話では出なくなったが、「眠れない」は確定版でも3回中2回「体の不調」と読んだ。プログラムで、眠れないだけの話は急な不調として扱わないようにした（`settled_ai_care`）。上の表と次の比較の案内は、この決まりを通した結果で、保存した AI の答えを通し直して確かめた。

- Haiku 5.5 が「家が静か」「さびしい」を「強いつらさ」と読み、相談窓口の案内が付く回があった。さびしいだけでは当てはめないとプロンプトに書くと、確定版の Haiku 5.5 3回と Sonnet 5.5 1回では付かなかった。
- 語の一覧で「腰」「眠れ」「薬」をそのまま見ると、「重い腰を上げて畑に行くべきかな」「よく眠れたから畑に出てもいいかな」「農薬をまいてもいいかな」にも相談先が付くので、語を絞った。
- 治し方の語（湿布、温める、冷やす、安静、体操、痛み止めなど）は、直した後のすべての回で体の相談への返事に出なかった。一方、今日の一言には「体を温めてから動くと楽に」と書いた回があったので、体の話への返事と今日の一言の両方で、語を見て外すようにした。

最近のログと今回の発言を渡すだけでは、「妻」がだれで、その人が本人にとって何なのかが分からない。実際に「帰宅したら妻が家にいるかと思った」に、ツインは「奥さんがいると思って帰られたのですね。玄関で声をかけたくなる日もありますね。」と返した。入力に、亡くなったという事実も、10年分の読みもなかった。

「知っているか」と聞かれたときは、聞いたことを本人の言葉で答える。聞いていないことは、言い切らず、聞いてきた話へやわらかく寄せる（tyumajinさんの決定。「まだ聞けていません」は本人には冷たく聞こえるため。専門職の問いの決まった文はそのまま）。目次の言葉は項目ごとに上限があるので、目次に載っていない言葉（記録にある命日など）は答えられないことがある。

1回の返事ごとに、書いた返事、落とした文と理由、画面の返事、モデル、トークン数、かかった時間を `inference_logs` の「ツインの読み」に残す。`python -m fiction.twin_trace データベース` で読む。

Haiku 5.5 に同じ目次を渡しても言い直しの返事が残ったので、目次があるときの返事はすべて Sonnet 5.5 で書く。目次がないときは今までどおり Haiku 5.5 で、発言の中身で選ぶ。

## ツインの会話でモデルを選ぶ（11/4）

発言の中身をプログラムが判断し、必要なときだけモデルを Sonnet 5.5 へ選択する（`app/twin_model.py`、`app/twin.py` の `choose_turn`）。判断は答えの前に1回だけで、選んだモデルが1回で返事を書く。AI には判断させない。毎回の費用と待ち時間が増え、判断もぶれるため。

| いつ | 判断すること | 選ぶ理由 | Haiku 5.5 を呼ぶか |
|---|---|---|---|
| 答えの前 | 体や命の場面、体や薬の相談（`detect_care`） | 言葉の加減の差が大きい。つなぎ先の文はどのモデルでもプログラムが添える | 呼ばない |
| 答えの前 | 相談の言葉、体の話、人生に関わる話、気持ちの話の語 | 同じ20件の比べで、案の有無と言葉の加減に差が出た | 呼ばない |
| 答えられないとき | 型に合う答えが出せない、断られた | 送信を失敗にしない。Sonnet 5.5 は拒否の代替も使える | 呼んだ後にもう一方で答える |
| 今日の一言 | 薬、湿布、受診の語か、診断や服薬の指示の言い切りがある | 服薬の指示と急ぐかの判定を出さない（原則17）。一般的な健康の工夫は出してよい。書き直しても残れば一言を出さない | 呼んだ後に送り直す |

重い話で終わった日に今日の一言を出さないかは、モデルを選ばず、同じ呼び出しの中で Haiku 5.5 が判断する。語の一覧では重い話の多くを拾えず、Sonnet 5.5 に替えても結果が変わらなかったため。比べは [decisions.md](decisions.md) の「重い話で終わった日は今日の一言を出さない」にある。

選んだモデルが答えられないときは、もう一方のモデルの答えを使う。本人を待たせて何も返さないより、言葉の質が少し落ちても返すほうがよいため。安全のつなぎ先はモデルの選択に関わらず、プログラムが添える。

比べは `scripts/compare_twin_voice.py --natural 40` で流せる。

物語の流し込みも同じ道を通るので、この切り替えが効く。流し込みの返事を約1,200回と見込むと、ツインの会話の費用は約 $0.6 から約 $2.9 に増える（見込みで、流して確かめた数字ではない）。

用意した20件の案内は、2回とも全部決まりどおりだった（体や薬の相談は相談先、膝の痛みとさびしい話は案内なし、胸の痛みは119番、限界の話は相談窓口）。治し方の語は返事に出なかった。

試して見つけたこと：

- 最初は「決めて」を相談の語にしていたので、「順番を決めて」にも反応し、ふだんの話の40件中3件が無駄に Sonnet 5.5 へ回った。「決めてくれ」などに絞った。
- プロンプトの例に「無理はなさらないでください」を書くと、Sonnet 5.5 がそのまま使い、用意した20件中6件で同じ文になった。例を外すと、確定版の2回とも0件になった。

残っていること：言葉の良し悪しは人が読んで比べたもので、数で採点はしていない。Sonnet 5.5 でも「誠一さんには重い話かもしれません」のように推測に近い文が出た回がある。語に当たらない相談は Haiku 5.5 が答える。

## 自分の記録を守るフック

開発者は、自分の本当の言葉と写真を `data/mine/` に入れ、このアプリを使いながら作っています。開発中の Claude Code は許可の確認を省いた設定で動くので、止める仕組みがなければ命令はそのまま実行されます。本物の記録を読むと AI に渡り、テストや文書に写れば公開リポジトリに入るおそれがあります。そこで、うっかり触れることをプログラムで止めます。

| 層 | 止めるもの |
|---|---|
| `deny`：`Read(/data/mine/**)`、`Edit(/data/mine/**)` | Read、Edit、Write などの道具で `data/mine/` に触れること |
| `deny`：`mcp__claude-in-chrome` | 実際の Chrome を操作する道具 |
| フック（PreToolUse） | Bash などの命令の中の `data/mine`、ポート 8001、`--mine`、`cp -r data` や `cat data/*/x` のような形 |

### 約束のテストのフックとの違い

| | 約束のテスト | 自分の記録を守る |
|---|---|---|
| 動く時 | 編集のあと | 道具を使う前 |
| 役割 | 壊したことに気づく | 触れる前に止める |
| 見るもの | テストの結果 | 道具の呼び出しの文 |

### 選んだ理由と、選ばなかった案

`deny` とフックを組み合わせました。コードを変えず、動いている自分用サーバーを止めずに入れられ、Bash の命令の中まで確かめられるためです。

| 選ばなかった案 | 理由 |
|---|---|
| `deny` だけ | Read や Edit の道具は止まるが、Bash の命令の中までは見ない |
| サンドボックス | OS のレベルで止められるが、公式の説明では macOS、Linux、WSL2 が対象で、Windows 上で直接動かす今の環境では使えない。開発環境を WSL2 へ移す必要がある |
| 保存先をリポジトリの外へ移す | 親のフォルダからの読み取りと `git add -f` の事故はなくなるが、コードの変更、サーバーの停止、データの移動が要る |

実際の Chrome の道具は、開いている画面を URL の指定なしで読めて、呼び出しの文では判断できません。そのため、フックではなく `deny` で道具ごと止めています。画面の確かめには Playwright を使います。

### 止められないこと

うっかり触れることを止める仕組みで、わざと避ける動きまでは止められません。次の形は、命令の文から読む先が分かりません。

- スクリプトを書いてから実行する
- 変数で道を組み立てる
- `grep -r x .` のように親のフォルダから読む

### 確かめた結果

テストは `tests/test_guard_own_records.py` の76件です（止めるもの41件、止めないもの34件、入力が読めないとき1件）。ポート 8001 への接続と `--mine` の起動は、実地では試さず、このテストで確かめています。

実地では、存在しないファイル名で確かめました。設定を置き換えたあと、再起動せずに効きました。

| 確かめたこと | 結果 |
|---|---|
| Bash で `ls data/mine/__guard_test__` | フックが止めた |
| Read で `data/mine/__guard_test__` | `deny` が止めた（フックまで届かない。フックの Read の判定はテストで確かめた） |
| Bash で `git ls-files data/mine` | 止まらず、何も出なかった（追跡は0件） |

`echo "$(git ls-files data/mine | wc -l)"` の形は止まりました。命令の結果を文に埋め込む形は読む動きになりうるので、止める側に倒しています。

## Claude Code で作ったことで、できるようになったこと

開発者は介護現場でケアマネジャーの業務を行っている一人です。次の数字は、下の出どころから取りました。

| 項目 | 数字 | 出どころ |
|---|---|---|
| 日数 | 2026-11-02 から 2026-11-08 まで（この数字を取った日まで）の7日 | `git log` の最初のコミットの日と、今のコミットの日 |

できるようになったことの例です。

- **フックで気づく**：本人の言葉の切り方を崩しても、最初のフックは気づかなかった。テストを足し、崩し方9通りで知らせが出ることを確かめた（この文書の「フックをわざと崩して確かめたこと」）。その後、編集の途中でプロンプトの文字列を壊したときも、約束のテストが落ちたと知らせた。
- **10年分を流して読んで欠けを見つける**：本物の処理に10年分を流し、できた記録を読んで次を見つけた。どれも小さな試しでは出なかった。
  - 長い本人の発言の一部の文だけが言明に入る（この文書の「本人の発言の一部が言明から落ちる」）。
  - 重い話のあとに夜の冷えの一言が付く（`docs/decisions.md` の「重い話で終わった日は今日の一言を出さない」）。
  - 出来事の言葉は要素の根拠に入らず、確かめた言葉でも届かないことがある（`docs/decisions.md` の「確かめた言葉を、空いた枠にだけ足す」）。
