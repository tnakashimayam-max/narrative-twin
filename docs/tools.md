## アプリの中の Claude

モデル名は `app/config.py` の1か所で決めます。「状態」は、処理がいま動いているかどうかです。

| 役割 | 状態 | モデル | 使う機能 | 選んだ理由 | 選ばなかった案 | 実測 |
|---|---|---|---|---|---|---|
| 接続確認 | 動く | Opus 5.5 | JSON 出力、拒否の代替 | 判断の重い役割で使うモデルまで届くかを確かめるため | 安いモデル：そのモデルに届くかが分からない | 11/2 に1回：入力294／出力9トークン、約$0.0014 |
| 写真の問い | 動く（本物の確認は写真を用意してから） | Sonnet 5.5 | 画像を読む力、JSON 出力 | 本人が待つ場面で、問いを1つ返すだけなので | Opus：費用が2倍で速さも落ちる。Haiku：写真の細部の読み取りを確かめていない | まだ測っていない |
| 言明への分割 | 動く | Sonnet 5.5（考える深さ medium） | JSON 出力、Message Batches API | 回数が多い。本人の言葉の一字一句はプログラムが確かめる | Opus：費用が2倍。品質が足りなければ切り替える | 短い会話3つ：1回あたり約$0.025、約10秒。バッチで47単位：$0.57、157秒（下の表） |
| 架空ログの作成 | 動く | Sonnet 5.5（考える深さ low） | Message Batches API | 決まった筋書きの文を大量に作るだけなので | Opus：判断の重さがなく費用が過剰 | 40回：$0.18、128秒（下の表） |
| ツインの会話 | 未作成 | Sonnet 5.5 | JSON 出力、プロンプトキャッシュ | 本人が返事を待つので、速さと言葉の質の釣り合いをとる | Opus：待ち時間と費用が増える | ― |
| スレッドの問い | 未作成 | Sonnet 5.5 | JSON 出力 | 入力が小さく、問いを1つ書くだけなので | Haiku：やさしい言葉の質を確かめていない | ― |
| 固める処理 | 未作成 | Opus 5.5 | JSON 出力、Message Batches API、プロンプトキャッシュ | 回数は少ないが、誤ると意思モデル全体に残るため | Sonnet：判断の質を優先した。Fable：費用が2.5倍で、まず Opus で足りるかを見る | ― |
| 推定意思 | 未作成 | Opus 5.5 | JSON 出力、プロンプトキャッシュ | ケアの判断の材料になり、誤りの影響が大きいため | Sonnet：同上 | ― |
| 原案 | 未作成 | Opus 5.5 | JSON 出力、プロンプトキャッシュ | 専門職が読み、根拠のつながりの質が要るため | Sonnet：同上 | ― |
| 根拠チェック | 未作成 | Opus 5.5 | JSON 出力 | 原案を疑う役割なので、原案と同じ強さにする | Sonnet：原案より弱いと見落としが増える | ― |

共通の機能：

| 機能 | 目的 | 選ばなかった案 |
|---|---|---|
| JSON 出力と Pydantic での検証。だめなら1回やり直す | 決めた型に合うものだけを受け取るため | SDK の `parse`：断られた応答が読み取りの失敗になり、断られたことが分からない |
| 拒否の代替（`fallbacks: "default"`） | 安全の確認で断られても、API の側で別のモデルに切り替えるため | なし。切り替わる場面は、通信を差し替えたテストでだけ確認 |

処理ごとの分担です。アプリの機能として動いている処理を書きます。未作成の役割は、作ったときに足します。

| 処理 | Claude が担うこと | プログラムが確かめること | 本人が決めること | 決まった手順だけでは足りない理由 |
|---|---|---|---|---|
| 言明への分割 | 発言を、1つの事実か考えごとの言明に分ける。<br>本人の言葉として抜き出す文を選ぶ。<br>出どころ、話した人と誰についてか（TSS）、時期、テーマ、花びらを付ける。<br>4つの視点の解釈（NAK-4V）を書く。<br>遠慮や建前の裏にありそうなことをAIの推測にし、確かめる問いの候補を書く。<br>（`app/prompts.py` の `SPLIT_SYSTEM`、`app/ai.py` の `split_utterances`） | 答えの型。合わなければ1回やり直す（`app/schemas.py` の `SplitResult`、`app/ai.py` の `call_structured`）。<br>本人の言葉が、発言の原文の文の切れ目から切れ目までの抜き出しか（`app/verbatim.py` の `quote_problem`）。問題があれば理由を伝えて1回やり直し、残りは捨てて数える（`app/intake.py` の `split_and_save`）。<br>話した人が出どころに合い、AIの推測を除いて根拠の発言の話し手と同じか（`app/ledger.py` の `_check_draft`）。<br>根拠の番号が入力にあるか、AIの推測が言い切っていないか、人の発言を根拠にしているか、問いの候補が1つで「合っていますか？」で終わるか（`app/splitter.py` の `_drop_reason`、`_is_hedged`、`_question_is_usable`）。<br>共有範囲は AI から受け取らず「本人だけ」、確認の状態は未確認、解釈は仮説で保存する。根拠に本人の発言がなければ、本人の真意は0.4までにして注意書きを付ける（`app/splitter.py` の `save_split`）。<br>呼べるのは本人だけで、同じ記録は2回分けない（`app/intake.py` の `_self_only`、`app/splitter.py` の `already_split`）。<br>解釈と花びらの中身の良し悪しは確かめない。 | 記録が合っているか（そうです／ちがいます／今は話したくない）と、見せる範囲。<br>AI の結果は未確認で「本人だけ」のまま止まり、AI の答えでは変わらない。<br>確かめる操作と範囲を広げる操作は、まだ作っていない。訂正は本人だけに限っている（`app/ledger.py` の `correct_statement`）が、API と画面はまだない。 | 1つの発言に、いくつもの考えが混ざる。誰についての話か、どの文に遠慮や建前があるかは、話の流れを読まないと決まらない。文の区切りや語の一覧では、この読み取りができない。 |
| 写真の問い | 写真に写っているものを読み、答えやすい問いを1つ作る。<br>（`app/prompts.py` の `PHOTO_SYSTEM`、`app/ai.py` の `ask_about_photo`） | 呼べるのは本人だけ。写真の形式と大きさ（`app/intake.py` の `_self_only`、`photo_question`）。<br>答えが1文で「？」で終わるか。合わなければ1回やり直す（`app/schemas.py` の `PhotoQuestion`、`app/ai.py` の `call_structured`）。<br>モデルとトークン数を記録する（`app/db.py` の `log_ai_call`）。<br>健康やつらい出来事を聞かないことは、プロンプトの決まりだけで、プログラムでは確かめていない。 | どの写真を見せるか。問いに答えるかどうか。<br>写真も問いも保存しない。画面に「ツイン（AI）」と付けて出すだけ（`static/app.js`）。答えを記録する処理は、まだ作っていない。 | 写真に何が写っているかは、決まった手順では読めない。決まった問いの一覧では、その写真に沿った問いにならない。 |

## フックをわざと崩して確かめたこと

`app/verbatim.py` を控えのコピーで崩し、フックの知らせを確かめました。本物のファイルは崩していません。

前のフックは `test_ledger`、`test_consent`、`test_ids` の3ファイルで162件でした。今のフックは `test_verbatim`、`test_splitter` を足した5ファイルで254件です。

| 崩し方 | 前のフックの3ファイル | 今のフック |
|---|---|---|
| 崩さない | 162件すべて通る | 254件すべて通り、知らせは出ない |
| 改行で始まりも終わりも切れるようにする | 162件すべて通る | 知らせが出る（2件落ちる） |
| 改行のあとから始められるようにする | 162件すべて通る | 知らせが出る（1件落ちる） |
| 改行の前で終われるようにする | 162件すべて通る | 知らせが出る（1件落ちる） |
| かっこの中身だけの本文を止める確かめを外す | 162件すべて通る | 知らせが出る（1件落ちる） |
| 閉じていないかっこの確かめを外す | 162件すべて通る | 知らせが出る（4件落ちる） |
| 上の2つの確かめを両方外す | 162件すべて通る | 知らせが出る（5件落ちる） |
| 発言全体を囲むかを、先頭と末尾の文字だけで決める | 162件すべて通る | 知らせが出る（1件落ちる） |
| 読点の前で切れるようにする | 162件すべて通る | 知らせが出る（1件落ちる） |
| 読点を切れ目にする | 162件すべて通る | 知らせが出る（3件落ちる） |

- `_SENTENCE_ENDS` に改行を足すだけでは、知らせは出ません。切れ目を見る前に空白と改行を飛ばすので、新しく入る切り方がないためです。乱数で作った発言で約203万通りを比べ、新しく入るものは0件でした。
- 崩さないときの時間は、フック全体で約25秒です。3ファイルのテストは約15秒でした。
- この確認は手で1回行いました。1通り約25秒かかるので、自動のテストには入れていません。
