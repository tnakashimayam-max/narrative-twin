# モデルと機能の表

目的を決めてから選びます。期待どおりに役立たなければ外し、理由を [decisions.md](decisions.md) に残します。

## アプリの中の Claude

モデル名は `app/config.py` の1か所で決めます。

| 役割 | モデルや機能 | 選んだ理由 | 選ばなかった案 | 実測 |
|---|---|---|---|---|
| 接続確認（`python -m app.ai`） | `claude-opus-5-5` | あとの処理で使う既定のモデルまで届くかを確かめるため | 安いモデル：既定のモデルに届くかが分からない | 11/2 に1回実行。モデルは `claude-opus-5-5`、入力294／出力9トークン |
| 結果の受け取り | JSON 出力と Pydantic での検証。だめなら1回やり直す | 決めた型に合うものだけを受け取るため | SDK の `parse`：断られた応答が読み取りの失敗になり、断られたことが分からない | テストで確認（通信は差し替え） |
| 断られたときの代替 | server-side fallback（`fallbacks: "default"`） | 安全の確認で断られても、API の側で別のモデルに切り替えられるため | なし | 11/2 の接続確認で指定が受け付けられた。実際に切り替わる場面は、通信を差し替えたテストでだけ確認 |

## 開発の Claude Code

設定は `.claude/agents/` にあります。

| 役割 | モデル | 選んだ理由 | 選ばなかった案 | 実測 |
|---|---|---|---|---|
| 設計担当（architect） | fable | 呼ぶ回数は少ないが、判断の誤りがあとの作業すべてに響くため | opus：判断の誤りの影響が大きい場面なので、より高い性能を選んだ | データの表の設計の確認：約6分、約4万トークン。番号の持ち方の確認：約6分、約6万トークン |
| 検証担当（verifier） | opus（節目の総点検だけ fable） | 呼ぶ回数が多いため | 常に fable：呼ぶ回数が多く費用が大きい | 1日目の土台の検証：約20分、約20万トークン。再確認：約9分、約14万トークン |
| UIUX担当（uiux-reviewer） | opus | 画面の良し悪しの判断は、使う人の安心に直結するため | sonnet：判断の質を優先した | まだ呼んでいない |
| 架空データ担当（data-maker） | sonnet | 決まった手順の作業が多いため。10年分の本文を作るモデルは別に選ぶ | opus：決まった手順の作業には性能が過剰 | まだ呼んでいない |
