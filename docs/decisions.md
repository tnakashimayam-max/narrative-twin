# 決めたことと、やめたこと

## データの設計で決めたこと（11/2）

設計担当の確認をもとに決めました。

| 決めたこと | 理由 |
|---|---|
| 決めた言葉は括弧の説明を除いた形にする（判断の決まり、縁のある人まで） | 括弧は説明で、値ではないため。「今の様子（観察）」は値の表にある形のまま使う |
| 意思モデルの要素に `previous_version_id`（前の版）を足す | 版の番号だけでは、本文や花びらが変わった版どうしをつなげないため |
| 話した人は「利用者の番号」と「ツインか」の2つの項目で持つ | ツインは役割の決めた言葉にないため。AIの推測が本人の発言に混ざるのを防ぐ |
| 誰についてかは利用者の番号で持つ | 本人についての言明を確実に選び出せるようにするため |
| 発言の「会話かスレッドの番号」は `conversation_id` と `letter_id` の2列に分ける | どちらの番号かを取り違えないため。チャットと会議は1回を1つの会話として持つ |
| コメントに `utterance_id` を足す | 本文を発言としても保存するので、その発言を指す必要があるため |
| 推論の記録に、モデル名とトークン数を足す | 処理の記録にモデルとトークン数を残す方針のため |
| 複数の番号や花びらは JSON の配列で持つ | いまは要素→言明→原文の順にたどるだけなので。番号が実在するかは表の決まりでは確かめない |
| 有効な期間、処理の期間、トークン数は2列に分ける（`valid_from`・`valid_to`、`period_start`・`period_end`、`input_tokens`・`output_tokens`） | 1つの列にまとめると、比べたり足したりできないため |
| 確からしさは 0〜1 の数で持つ | 比べたり並べたりできるようにするため。数字のまま画面に出すとは決めていない |
| 発言の表も追記だけにする | 言明が原文の抜き出しであることは、原文が変わらないから保てるため |
| 一覧の並びで、証言は本人の言葉のあと、AIの推測の前に置く | 今の様子 → 本人の言葉 → AIの推測の順を保ち、証言の位置を決めるため |
| 隠れる行がある9つの表の番号を、1〜2^53−1 の乱数にする | 通し番号の飛びから「本人だけ」の記録の数が分かるため。JavaScript で安全に扱える範囲にした |
| 番号の列は `id INTEGER NOT NULL UNIQUE` にし、並びは時刻と `rowid` で決める | 指定し忘れを止められ、追記の順を応答に出さずに残せるため。新しい列は足していない |
| 会話、便り、コメントの追記の関数を、今 `ledger` に作る | データの読み込みも `ledger` を通すため。番号を作る場所も1か所になる |
| 出どころごとに書ける話し手を決め、追記のときに止める | 出どころを偽れないようにするため。表は [architecture.md](architecture.md) にある |
| 根拠の発言がない言明は入れない | どの発言から作ったかをたどれなくなるため |
| 確認の状態は未確認から始める。確認済みとお休みは本人の操作でだけ、訂正済みは訂正でだけ付ける | 他の人の賛同やAIの要約で確認済みにしないため |
| 訂正前の文は本人にだけ見せる。本人以外が番号で開けるのは連鎖の先頭の行だけ | 訂正された記録は訂正後の文を届ける決まりのため。見える範囲の判断も先頭の行の共有範囲だけで済む |
| 質問の記録の、聞いた日と結果は空でもよい | まだ聞けていない質問を入れるため |
| 本人の言葉は、文の切れ目で始まり終わるものだけ入れる。切れ目は原文の先頭と末尾、「。」「！」「？」だけ。読点と改行では切らない | 「家で暮らしたいとは思いません。」から「家で暮らしたい」を抜き出すと、一字も変えなくても意味が逆になるため。文の途中の改行でも同じことが起きる |
| かぎかっこの中だけの抜き出しは入れない。発言全体がかっこで囲まれているときだけ、内側を発言として扱う | 他人の言葉を本人の言葉にしてしまうため |
| 話した人は、根拠の発言の話し手と同じでなければならない（AIの推測を除く） | 別の人の発言を、AI の答えで美穂さんの証言などにさせないため |
| 根拠に本人の発言がない言明は、本人の真意の確からしさを 0.4 までにし、決まった注意書きを必ず付ける | 本人が別の発言をしている会話でも、家族の見方を本人の真意として強く持たないため |
| 文の切れ目から外れた抜き出しは、広げて救わず、やり直しのあと捨てて数える | 花びらや解釈は短い本文を読んで付けたものなので、広げると本文と食い違うため。入った誤りは確認済みになると取り返しにくい。発言の原文は残るので作り直せる |
| AI の結果の言明は、共有範囲を AI から受け取らず、一律「本人だけ」で保存する | 見せる範囲は本人が決めるため。いちばん狭く、あとで戻しやすい |
| AI の呼び出しの記録の表（`ai_calls`）を足す | 言明への分割は推論の記録の種類に入らないが、モデルとトークン数を残す方針のため。戻すときは表を消すだけでよい |
| 同じ記録を2回分けないよう、その発言を根拠にした言明がすでにあれば 409 を返す | 2回分けると言明が重なるため。呼び出しの記録で判定すると、失敗した記録をやり直せなくなる。処理済みの印の持ち方を決めるまでの仮の形で、固める処理の前に見直す |
| スレッドを分けるときは、便りの本文を文脈として渡す。番号は振らず、根拠にしない | コメントが何を指すかが AI に分かるようにするため。戻すときは1行消すだけでよい |
| ツインの問いだけを根拠にしたAIの推測は捨てる | AI の問いから AI が推測すると、本人の記録に根拠がなくなるため |
| AI に渡す発言の番号は、1始まりの仮の番号にする | 本当の番号は53ビットの乱数なので、書き写すと誤りやすいため |
| 言い切ったAIの推測は捨てる | 推測は言い切らない決まりのため。文ごとに文末の形で確かめる |
| 確かめる問いの候補は、問いが1つで「合っていますか？」で終わるものだけ残す。「つらかったこと」は残さない | 問いは1回に1つで、つらい出来事は AI から聞かないため |

## まだ決めていないこと

| 内容 | いまの状態 |
|---|---|
| 処理した会話の数、意思モデルの大きさ、仮説を固め直した回数、処理済みの印の置き場 | 固める処理を作る前に、列を足すか、ほかの表から求めるかを決める |
| 共有範囲の変更の持ち方 | 新しい行の追記で持つ案がある。処理は作っていない。AI の結果の言明は「本人だけ」で入るので、デモの意思決定支援用の記録にはこの処理が要る。絞り込みは、広げる向きと狭める向きの両方を確かめてある |
| お休みにした記録を、家族などに見せ続けるか | 処理を作るときに決める |
| ライセンス | 提出までに決める |

## 検討してやめたこと

| やめた案 | 理由 |
|---|---|
| 「確認の出来事」の表を別に作る | 確認も言明の新しい行で表せるので、表を増やさない |
| 意思モデルの要素に共有範囲の列を持つ | 根拠の言明から決められるので、持つと食い違いの元になる |
| AIの呼び出しに SDK の `parse` を使う | 試したところ、断られた応答でも読み取りの失敗になり、やり直してしまった。`create` で受け取ってから検証する形に変えた |
| 接続確認に安いモデルを使う | 既定のモデルに届くかを確かめられないため |
| 番号を `INTEGER PRIMARY KEY` のまま、アプリが作って渡す | 指定し忘れると通し番号が付き、止められないため |
| 番号の列を `WITHOUT ROWID` で持つ | 指定し忘れは止まるが、並び順のために新しい列が要るため |
| 時刻を含む番号（ULID など）を使う | 番号から順番と時刻が読めるため |
| 本人以外への応答でだけ番号を別の形に変える | 番号が2種類になり、取り違えの元になるため |
| 番号で開くとき、開いた行と先頭の行の両方の範囲を確かめる | 本人以外は先頭の行しか開けなくなったので、いらなくなった |
| 通し番号の飛びを限界として受け入れる | 「本人だけ」の記録は件数も返さない決まりに反するため |
