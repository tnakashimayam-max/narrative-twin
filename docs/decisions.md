# 決めたことと、やめたこと

## データの設計で決めたこと（11/2）

設計担当の確認をもとに決めました。

| 決めたこと | 理由 |
|---|---|
| 決めた言葉は括弧の説明を除いた形にする（判断の決まり、縁のある人まで） | 括弧は説明で、値ではないため。「今の様子（観察）」は値の表にある形のまま使う |
| 意思モデルの要素に `previous_version_id`（前の版）を足す | 版の番号だけでは、本文や花びらが変わった版どうしをつなげないため |
| 話した人は「利用者の番号」と「ツインか」の2つの項目で持つ | ツインは役割の決めた言葉にないため。AIの推測が本人の発言に混ざるのを防ぐ |
| 誰についてかは利用者の番号で持つ | 本人についての言明を確実に選び出せるようにするため |
| 発言の「会話かスレッドの番号」は `conversation_id` と `letter_id` の2列に分ける | どちらの番号かを取り違えないため。チャットと会議は1回を1つの会話として持つ |
| コメントに `utterance_id` を足す | 本文を発言としても保存するので、その発言を指す必要があるため |
| 推論の記録に、モデル名とトークン数を足す | 処理の記録にモデルとトークン数を残す方針のため |
| 複数の番号や花びらは JSON の配列で持つ | いまは要素→言明→原文の順にたどるだけなので。番号が実在するかは表の決まりでは確かめない |
| 有効な期間、処理の期間、トークン数は2列に分ける（`valid_from`・`valid_to`、`period_start`・`period_end`、`input_tokens`・`output_tokens`） | 1つの列にまとめると、比べたり足したりできないため |
| 確からしさは 0〜1 の数で持つ | 比べたり並べたりできるようにするため。数字のまま画面に出すとは決めていない |
| 発言の表も追記だけにする | 言明が原文の抜き出しであることは、原文が変わらないから保てるため |
| 一覧の並びで、証言は本人の言葉のあと、AIの推測の前に置く | 今の様子 → 本人の言葉 → AIの推測の順を保ち、証言の位置を決めるため |
| 隠れる行がある9つの表の番号を、1〜2^53−1 の乱数にする | 通し番号の飛びから「本人だけ」の記録の数が分かるため。JavaScript で安全に扱える範囲にした |
| 番号の列は `id INTEGER NOT NULL UNIQUE` にし、並びは時刻と `rowid` で決める | 指定し忘れを止められ、追記の順を応答に出さずに残せるため。新しい列は足していない |
| 会話、便り、コメントの追記の関数を、今 `ledger` に作る | データの読み込みも `ledger` を通すため。番号を作る場所も1か所になる |
| 出どころごとに書ける話し手を決め、追記のときに止める | 出どころを偽れないようにするため。表は [architecture.md](architecture.md) にある |
| 根拠の発言がない言明は入れない | どの発言から作ったかをたどれなくなるため |
| 確認の状態は未確認から始める。確認済みとお休みは本人の操作でだけ、訂正済みは訂正でだけ付ける | 他の人の賛同やAIの要約で確認済みにしないため |
| 訂正前の文は本人にだけ見せる。本人以外が番号で開けるのは連鎖の先頭の行だけ | 訂正された記録は訂正後の文を届ける決まりのため。見える範囲の判断も先頭の行の共有範囲だけで済む |
| 質問の記録の、聞いた日と結果は空でもよい | まだ聞けていない質問を入れるため |
| 先頭と末尾が組のかっこで全体を囲んでいない発言では、その2文字を含む本文を入れない（`_includes_outer_marks`）。「帰りましょう。」と妻。「施設は嫌だ。行きたくない」の「帰りましょう。」と妻。は入らない | 誤って入れるより、捨てるほうへ倒す方針に合うため。発言がかっこで始まるかどうかで扱いが変わるが、残している |
| 本人の言葉は、文の切れ目で始まり終わるものだけ入れる。切れ目は原文の先頭と末尾、「。」「！」「？」だけ。読点と改行では切らない | 「家で暮らしたいとは思いません。」から「家で暮らしたい」を抜き出すと、一字も変えなくても意味が逆になるため。文の途中の改行でも同じことが起きる |
| かぎかっこなどのかっこの中からの抜き出しは入れない。本文の始まりより前に閉じていないかっこがあれば止め、本文がかっこの中身だけのものと、本文の中でかっこが閉じないもの（和子は「もう無理です。）も止める。かっこが閉じている本文は入れる。発言全体を囲むと扱うのは、最初のかっこに対応する閉じかっこが発言の末尾にあるときだけで、そのときは内側を発言として扱う | 他人の言葉を本人の言葉にしてしまうため。先頭と末尾の文字だけで決めると、「帰りましょう。」と妻。「施設は嫌だ。行きたくない」を囲まれた発言と誤って扱うため |
| 話した人は、根拠の発言の話し手と同じでなければならない（AIの推測を除く） | 別の人の発言を、AI の答えで美穂さんの証言などにさせないため |
| 根拠に本人の発言がない言明は、本人の真意の確からしさを 0.4 までにし、決まった注意書きを必ず付ける | 本人が別の発言をしている会話でも、家族の見方を本人の真意として強く持たないため |
| 文の切れ目から外れた抜き出しは、広げて救わず、やり直しのあと捨てて数える | 花びらや解釈は短い本文を読んで付けたものなので、広げると本文と食い違うため。入った誤りは確認済みになると取り返しにくい。発言の原文は残るので作り直せる |
| AI の結果の言明は、共有範囲を AI から受け取らず、一律「本人だけ」で保存する | 見せる範囲は本人が決めるため。いちばん狭く、あとで戻しやすい |
| AI の呼び出しの記録の表（`ai_calls`）を足す | 言明への分割は推論の記録の種類に入らないが、モデルとトークン数を残す方針のため。戻すときは表を消すだけでよい |
| スレッドを分けるときは、便りの本文を文脈として渡す。番号は振らず、根拠にしない | コメントが何を指すかが AI に分かるようにするため。戻すときは1行消すだけでよい |
| ツインの問いだけを根拠にしたAIの推測は捨てる | AI の問いから AI が推測すると、本人の記録に根拠がなくなるため |
| AI に渡す発言の番号は、1始まりの仮の番号にする | 本当の番号は53ビットの乱数なので、書き写すと誤りやすいため |
| 言い切ったAIの推測は捨てる | 推測は言い切らない決まりのため。文ごとに文末の形で確かめる |
| 確かめる問いの候補は、問いが1つで「合っていますか？」で終わるものだけ残す。「つらかったこと」は残さない | 問いは1回に1つで、つらい出来事は AI から聞かないため |

## トークと共有の設計で決めたこと（11/2 夜）

設計担当に相談して決めました。見える人がいちばん狭く、あとで戻しやすい案を選びました。

### ツインが前の話をどう覚えるか（仮。固める処理ができたら置き換える）

| 決めたこと | 理由 |
|---|---|
| 1回の呼び出しに、今の会話の発言（新しい40発言、8,000字まで）、過去の会話の要約（新しい10会話、各300字まで）、前に聞いた本人の言葉（新しい40言明、4,000字まで）、聞いた問い（新しい30件）と確かめる問いの候補（5件）、お休みの話題を渡す | 記録が増えても読む量を増やさないため。合計は約18,000字で、Haiku の高い値段（10万トークン超）にならない |
| 要約は「今日はここまで」のときの呼び出しでは作らず、閉じたあとの裏の処理で作る | 日付が変わって自動で閉じる道では別れの呼び出しがなく、要約が欠けるため |
| 要約がまだない直前の会話は、新しいほうから20発言をそのまま渡す | 閉じた直後に送り直す場面や、分割が失敗した場面で忘れないため |
| 前に聞いた本人の言葉には、ツインとの部屋から来た本人の言葉と本人の訂正だけを入れる。証言、AIの推測、グループとスレッドの発言は入れない | 家族の言葉を本人の意思として扱わないため。招かれた部屋の話を別の部屋へ持ち出さないため |
| 写真は最初の返事で Sonnet が読み、説明（120字以内）を photos の表に残す。あとの呼び出しでは、AI の読み取りと分かる形で渡す。説明を渡すのはツインとの部屋だけ | あとの Haiku は写真を見ないので、見たものを文で残す |
| 要約は AI の読み取りとして渡し、本人の言葉として扱わない。過去の言葉に触れるときは原文を使うか、「〜とうかがった気がします。合っていますか？」の形にする | 本人の言葉を言い換えないため |
| お休みの話題は、質問の記録の結果が「お休み」のテーマから読む。本人が問いを断ったら直前の問いをお休みにする。問いの吹き出しの「この話はお休みにする」でも決められる。言明の確認の状態は変えない | 誤って休ませても聞かない向きなので害が小さく、質問の記録は直せるので戻せる。言明の確認は確認の画面を作るときに決める |

### 問いの選び方（仮。固める処理ができたら置き換える）

| 決めたこと | 理由 |
|---|---|
| 写真か日記の内容、今の会話、前に聞いた本人の言葉、質問の記録から選ぶ。同じ質問をくり返さない。お休みの話題とつらい出来事は聞かない | 意思モデルができるまでの仮の決まり |
| 問いの数、お休みのテーマ、同じ問い、本人が終えたそうなときの問いは、AI の答えをプログラムが確かめて落とす | AI へのお願いだけでは守られるとは限らないため |

### 会話の区切りと、言明に分ける時

| 決めたこと | 理由 |
|---|---|
| ツインとの部屋は「今日はここまで」で会話を閉じ、裏で言明に分ける。次に送ると新しい会話になる | 本人を待たせないため |
| 送ったときに、開いている会話の日付が今日でなければ先に閉じる | 閉じ忘れを、日付の違いで1行で判定できるため |
| どこまで分けたかの印を split_marks の表に持つ（対象の種類、番号、発言の rowid）。会話もスレッドもグループも同じ表にする。同じ記録を2回分けると 409 にする形はやめ、新しい発言がなければ 0 件の報告を返す | 発言は追記だけなので rowid は増えるだけ。日付を手で指定しても追記の順で判定できる |
| 印の値は、AI に渡す前に読んだ最大の rowid にする | AI を待つ間に届いた発言を飛ばさないため |
| 印より前の発言は文脈として番号なしで渡し、根拠にできないようにする | 新しい発言の意味が分かるようにしつつ、2回分けないため |
| 印より後に人の発言がなければ AI を呼ばず、印も進めない | ツインの発言だけのときに費用をかけないため |
| 裏の処理は BackgroundTasks で動かし、処理の中で接続し直す。対象ごとのロックを取り、保存のあとで新しい発言が残っていればもう一巡する | 1つのプロセスなのでプロセス内のロックで足りる。待たせても発言を失わない |
| 裏の処理の失敗は job_failures の表に残す。中身は入れず、処理の名前と例外の種類だけを残す | 応答のあとに起きるので、黙って失われると「覚えていない」原因が追えないため |
| 起動のときに未処理を流し直す。テストが本物の API を呼ばないよう、`python -m app` の入口からだけ呼ぶ | 分ける途中で止まっても、やり直せるようにするため |

### 人、部屋、メッセージの表

| 決めたこと | 理由 |
|---|---|
| 人は users の表に列を足して持つ。新しい人の番号は乱数にする。亡くなった方とはずした人はログインできない。はずした人は部屋の人でもなくなる | 4人固定の前提を外すため。一覧から消すだけでは、別のウィンドウで開いたままの人に見え続けるため |
| 親子と夫婦の関係は family_links の表に持つ | 家系図の3世代を求めるため |
| ツインとの部屋も rooms の1行にし、表示は3種類とも room_messages を読む。ツインとの部屋とツインがいる間のグループは、発言を utterances にも ledger を通して入れ、本文は utterances にだけ持つ。人だけの部屋の本文は room_messages にだけ持つ | AI に渡す処理は utterances しか読まないので、人だけの部屋とツインが入る前の発言が AI に渡らないことを、表の形で守れる |
| グループにツインが入るたびに会話を1行作る。ツインが読むのはその会話の発言だけ | ツインが入る前の発言と、前に入っていたときの発言を渡さないため |
| 発言の場所に「グループ」を足す | チャットは専門職との会話に取っておくため |
| 決めた言葉の確かめを、表の CHECK からトリガーに移す | 追記だけの表を作り直さずに言葉を足せるようにするため。本人の言葉は作り直せないので、表の作り直しは避ける |
| 表の変更は、番号つきの追加だけの手順で行い、適用の前にデータベースのファイルを隣に控える | 本人の記録を失わないため |
| 古い形のデータベースは起動を止めて知らせる。手元の古い架空用のファイルは別名に移した | 形の合わない表で動かすと、途中で失敗するため |
| つながりの地図の線の強さと向きは map_links の表に本人が選んだものだけを持つ。AI の候補の表には持たない | 人の仲を AI が決めて記録に残さないため |
| グループは本人のほかに1人からでも作れる。作ったあとで人を足す操作は作っていない | 本人と妻とツインの3人で話す場面があるため。人を足す操作は、いちばん狭い案として今は作らず、作り直してもらう |

### 写真

| 決めたこと | 理由 |
|---|---|
| 見てよいかは参照元から毎回求める。持ち主、その写真を指す部屋の人、その写真を指す便りの共有範囲の人、はずされていない人のプロフィール写真。本人だけの特例は作らない | 本人はすべての部屋の人なので結果は同じで、特例が減る |
| 写真を返す道は中身だけを返し、種類、持ち主、説明を返さない | 便りに会話の写真を載せても、会話の情報が漏れないようにするため |
| サーバーでも開き直して1568px以下の JPEG にし、撮影の情報を落とす。すべて JPEG にそろえる。受け付けるのは10MBまで | 画面の処理を信じないため。保存と AI への受け渡しを1つの形で済ませるため |
| AI に写真を送る関数は「会話」の写真だけを受け付ける。プロフィール写真は送らない | プロフィール写真を AI に送らないことを、関数の入口で守るため |

### ログイン

| 決めたこと | 理由 |
|---|---|
| cookie をやめ、ウィンドウごとの番号をヘッダー `X-NT-User` で送る | 同じブラウザの2つのウィンドウで別の人として使えるようにするため。2つの方式を残すと取り違えの元になるため |

### 検証担当の指摘を受けて決めたこと

| 決めたこと | 理由 |
|---|---|
| プロフィールに指定できるのは、操作する人が送ったプロフィールの種類の写真だけ | 番号を指すだけで、便りや部屋の写真を全員に見せられたため |
| かっこの確かめを “ ” 〝 〟 〈 〉 《 》 〔 〕 ［ ］ ｢ ｣ " ' にも広げる。発言全体を囲むと扱う決まりも同じにする | 「 」以外の引用符で、他人の言葉が本人の言葉として通ったため。本人の言葉の確かめを変えるので、確認を残す |
| ツインの文で本人の言葉を伝える形は、原文と照らせるものだけを通す。グループの答えで本人の考えや発言を伝える文は、決まった文に替える | 本人の言葉を番号で取り出して届ける処理がまだなく、AI が作った「おっしゃいました」を確かめられないため |
| 改行のある発言は、AI に渡すときだけ JSON の文字列にする | 本文の中の「誠一さん：〜」が本人の行に見えたため。保存する原文は変えない |
| ツインの呼び名と、ほかの人の名前や呼ばれ方は使えない。断る理由は1つの文にそろえる | 本人やツインになりすませたため。各人が自分の名前を直せる決まりがあるので、断られたことから一覧に出ない人の有無を読むことは完全には防げない。残している |
| ツインとの部屋の入力に入れる問いの候補は、ツインとの部屋の発言から作ったものだけ | グループとスレッドから生まれた問いが持ち込まれたため |
| 名前は完全に同じものを先に探し、かっこの中が立場の言葉のときだけ外して探す | かっこのある名前で言明が落ち、別の人に結びつくことがあったため |
| 人どうしの部屋に付けられるのは部屋の写真だけ。写真の説明はツインとの部屋でだけ使い、話した人の行にしない | 説明が別の部屋へ渡り、本人の発言のように見えたため |
| AI を待つ間にツインをはずされたら、答えを書かない | はずれたあとに問いが書かれたため |
| グループとスレッドの読む量にも上限を置き、言明への分割も1回に40発言までにする | 約23万字の入力になる場面があったため |
| 写真のコメント欄も落とす。壊れた写真は読めない写真として扱う | 画面を通さず送るとコメントが残り、壊れた PNG で 500 になったため |

### 2回目の検証を読んで決めたこと

| 決めたこと | 理由 |
|---|---|
| 受け止めの文から、気持ちを決めつける言い方の文を、プログラムで外す。やり直しはしない | 決まりをプロンプトに足しても「大切にされているのですね」が出たため。返事を待たせず、失敗も増やさないため |
| 受け止めの文から、本人が今の発言で触れていない体とつらさの話の文を外す | 「庭の写真です。」に、前の話の胸の痛みを持ち出したため（原則6） |
| care は今の発言だけで決めるよう、プロンプトに書く。AI の判定は残す | 前の話の言葉で、関係のない発言に相談先の案内が付いたため。語の一覧にない言葉を拾うには AI の判定がいるので、消さない |
| 人の候補は「さん」などの有無だけの違いを同じ人として見る | 登録ずみの美穂さんが、「美穂」として候補に出たため |

### そのほかの仮の決めごと

| 決めたこと | 理由 |
|---|---|
| 命に関わる言葉と体の急な不調には、AI の判定に語の一覧を重ね、つなぎ先の文をプログラムが添える。よりそいホットラインの番号は厚生労働省の案内で確かめた | AI が断ったり見落としたりしても、つなぎ先を必ず出すため |
| 便りの本文は、本人が直すときは500字まで受け付ける。下書きは120字以内 | 本人が足したい言葉を切らないため |
| 検証のために日付を変える道は、架空用の起動だけに作る | 日を変えた会話を確かめるため。本物の記録の日付を動かさないため |

## 開発のログで決めたこと（11/3）

開発者が自分の記録で試しながら作っているので、起きたことを開発中に読めるようにしました。

| 決めたこと | 理由 |
|---|---|
| 架空用のログ（`logs/fictional.jsonl`）には、発言、AI の入力と答えも書く | ツインの返事がなぜそうなったかを追うため |
| 自分用のログ（`logs/mine.jsonl`）には、操作の種類、時刻、かかった時間、結果、エラーの種類、文字数、トークン数だけを書く。入力の文、AI の返事、写真、人の名前は書かない | 本人の記録を、開発の道具から読める場所へ写さないため |
| 自分用で通す項目と値の形を `app/devlog.py` の1か所で決め、ほかは捨てる | 呼ぶ側の書き忘れや誤りで本文が混ざらないようにするため。`tests/test_devlog.py` で、書き出されたファイル全体を確かめる |
| 自分用のログでは、モデル名、会話の番号、問いのテーマ、care を書かない | 決めた項目の外にあり、テーマと care は話の内容が分かるため |
| 例外は種類の名前だけを書き、説明の文を書かない。自分用では発生場所も書かない | Pydantic や SQLite の例外の文には入力が混ざることがあるため |
| リクエストの本文は読まず、処理の途中で必要なものだけを渡す | 架空用でも、写真のデータと人だけの部屋の本文をログに入れないため（原則15） |
| ログは `data/` の外の `logs/` に置き、Git に入れない | `data/mine/` の中は開発の道具から読めないようにしているため。自分用の記録を `data/mine/` の中だけに保つ約束（`tests/test_modes.py`）も変えないため |
| 問いを落とした、受け止めを短くした、決まった文に替えた、を結果の言葉で残す | 本文を見ずに、プログラムの決まりがどれだけ働いたかを数えるため |
| データベースの表にせず、ファイルに書く | 自分用の記録の表を変えずに入れるため |

## 意思モデルと田中さんのチャットで決めたこと（11/3）

設計担当に案を確かめてもらい、指摘を受けて次のように決めました。

| 決めたこと | 理由 | 選ばなかった案 |
|---|---|---|
| 託す範囲は本人がテーマで決める。選んだテーマの言葉は、未確認も含めて「意思決定支援用」の新しい行にする。専門職の画面に「本人が確かめた」「まだ確かめていない」と出す | 確認済みだけにすると、未確認の言明を根拠に持つ月と年の要素がほぼ隠れる。範囲を決めるのは本人のまま（原則10）で、確かめたかどうかは表示で分ける（原則3） | 確認済みの行だけ広げる：要素の大半が田中さんに見えなくなる |
| 本人が「今は話したくない」と答えた言葉は「本人だけ」に戻す | 話さない自由を守り、見える範囲の判断を `consent` の1か所に保つため（原則6） | 範囲はそのままにして表示だけ隠す：判断が2か所に分かれる |
| 田中さんへの答えの AI の呼び出しは1回にする。AI は要素の番号を選ぶだけで、引用はプログラムが選ばれた要素の根拠から決める | AI が本人の言葉の本文を読まないので、言い換える道がない（原則9） | 選ぶ役と届ける役の2回：本文を AI に見せる必要がなく、費用も増える |
| 要素が見えるのは、根拠の先頭の行がすべて見えるときだけ | 隠れた根拠があると、要素の本文から「本人だけ」の中身が漏れるため（原則10） | 一部が見えれば見せる |
| 要素の根拠の和集合に上限を置かない | 上限があると、残す根拠で見える範囲が変わり、たどりも切れるため | 上限つき |
| 確認の入力は、部屋のない「確認」の会話に発言として置く | 今日の会話に置くと、裏の分割が別の言明を作って二重になるため | 今日の会話に置く |
| 月の固める処理は Sonnet 5.5、年と人生の段階は Opus 5.5、バッチで行う | 月は抜き出しに近く回数が多い。年と段階は回数が少なく、変化の判断の質が要るため | すべて Opus：作り直しのたびに費用が膨らむ |
| 「10年後へ進む」のあと、2026年の年と人生の段階を流し直す | その場で入れた言葉が年の要素の根拠に入り、田中さんに届くようにするため | 月の要素だけに置く：読む量の上限で落ちる |
| 画面に「10年分・○回」の回数を出さない | 成長に数字を出さないと決めているため（原則13） | 回数を出す |
| 崩す頼みには決まった1文を添え、通常の処理も流す | 出力の道が構造的に安全なので、断って終わりにしなくてよいため。語の一覧を AI の判定に重ねる | 断って終わる |
| 直接答える要素がないときは、2回目の呼び出しで根拠の本文を読み、問いの事柄そのものを本人が話している言葉の番号を受け取る。あれば本人の言葉として本文のまま届け、推定は出さない | 要素の文には細かい事柄が残らない。「好きな食べ物は？」に、記録に「和子の味噌汁が好きだな。」があるのに「まだ聞けていません」と答えていた（下の表） | 語の一致で探す：「好きな食べ物」と「味噌汁が好き」は語が重ならない。要素の文を細かくする：読む量の上限に当たる |

## 「10年後へ進む」の前へ戻す道具で決めたこと（11/3）

| 決めたこと | 理由 | 選ばなかった案 |
|---|---|---|
| 控えは最初の起動と進む直前に自動で取り、前の控えを上書きしない | 進む直前だけでは、そこまでの入力と訂正の場面を撮り直せない。押し忘れがないよう自動にする | 手で取るだけ：取り忘れると戻せない。最新の1つだけ残す：戻したあとの2回目で前の控えが消える |
| 控えを取れなければ進まない | 進むと戻れないので、戻す手段がないまま進ませない | 取れなくても進む |
| サーバーは道具から止めず、動いていれば戻さない | 動いているプロセスをポートから探して止めると、別のものを止めるおそれがある。止めるのは Ctrl+C の1操作で足りる | 道具がポートの番号からプロセスを止める |
| 戻す前のデータベースと写真は消さず `data/trial/replaced/` へ移す | 撮り直したあとで前の状態が要ることがある。控えも架空のデータだけなので、Git の外に置いておける | 上書きする |
| 命令に場所の引数を持たせない。自分用の起動と、`mine` というフォルダを含む場所は断る | 開発者の記録を誤って指す道をなくすため | 場所を引数で受け取る |
| 控えは SQLite の backup で取る | サーバーが動いていて WAL に書きかけがあっても、そろった中身を写せるため | ファイルのコピー：WAL の中身が入らない |

## 検討してやめたこと

| やめた案 | 理由 |
|---|---|
| 「確認の出来事」の表を別に作る | 確認も言明の新しい行で表せるので、表を増やさない |
| 意思モデルの要素に共有範囲の列を持つ | 根拠の言明から決められるので、持つと食い違いの元になる |
| AIの呼び出しに SDK の `parse` を使う | 試したところ、断られた応答でも読み取りの失敗になり、やり直してしまった。`create` で受け取ってから検証する形に変えた |
| 接続確認に安いモデルを使う | 既定のモデルに届くかを確かめられないため |
| 番号を `INTEGER PRIMARY KEY` のまま、アプリが作って渡す | 指定し忘れると通し番号が付き、止められないため |
| 番号の列を `WITHOUT ROWID` で持つ | 指定し忘れは止まるが、並び順のために新しい列が要るため |
| 時刻を含む番号（ULID など）を使う | 番号から順番と時刻が読めるため |
| 本人以外への応答でだけ番号を別の形に変える | 番号が2種類になり、取り違えの元になるため |
| 番号で開くとき、開いた行と先頭の行の両方の範囲を確かめる | 本人以外は先頭の行しか開けなくなったので、いらなくなった |
| 通し番号の飛びを限界として受け入れる | 「本人だけ」の記録は件数も返さない決まりに反するため |
