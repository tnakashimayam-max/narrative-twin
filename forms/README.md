# 専門職の書式

専門職のツールで使う書式の定義です。資料を読み取るときと紙に出すときに、同じ欄の名前と並びを使うために置いています。読み込む処理は `app/care_forms.py` です。

## 何があるか

| ファイル | 書式 | 使い方 |
|---|---|---|
| `assessment.json` | アセスメントシート | 入力。心身と暮らしの状態を、選ぶ欄と詳細の欄で書く |
| `face_sheet.json` | フェイスシート | 入力。基本の情報、医療機関、連絡先、心身と暮らしの様子、生活歴 |
| `life_support_plan.json` | ライフサポートプラン | 入力。個々の目標、当面の目標（2つ）と目標プロセス、サービス、モニタリング |
| `life_plan.json` | 生活まとめプラン | 出力の紙（A4 横）。暮らしの場面15行 × 今まで、出来ること、出来ないこと、支援して欲しいこと、誰が。ツイン（AI）が下書きし、専門職が直して出す（`app/life_plan.py`、`static/life_plan.html`）。もとは事業所の生活アセスメントの紙 |
| `life_support_plan_print.json` | ライフサポートプラン | 出力の紙（A4 横）。どの欄を紙のどこに入れるかを `from` で持つ |

## もとにしたもの

開発者（tyumajinさん）の事業所で使っている書式です。業務システムの入力画面と仕様書、白紙の Excel の書式から、欄の名前、並び、選択肢、紙の列の幅の比を、ハッカソンの期間中（2026-11-06）に書き起こしました。

次のものは入れていません。

- 業務システムのコード（ハッカソンの決まりで、自社の介護ソフトのコードは使わないため）
- 事業所の名前、システムの番地や鍵、実在の人の情報
- 業務システムの管理のための欄（記録の番号、利用者の番号、期間の番号、作成の区分）と、使っていない余りの列

アセスメントシートの項目の多くは、要介護認定の認定調査票（基本調査）と同じ事柄を聞いています。

生活まとめプランの紙は、生活アセスメントの2016年4月の白紙をもとにしました（名前は tyumajinさんの決定）。2025年5月の白紙も項目は同じで、列の幅だけが違います（出来ること、出来ないことが広い）。

## 欄の型

| 型 | 中身 |
|---|---|
| `text` | 短い文 |
| `long_text` | 長い文 |
| `date` | 日付 |
| `number` | 数 |
| `select` | 1つ選ぶ。選択肢は `choices`、または共通の組 `choice_set`（`choice_sets` にある） |
| `multi_select` | いくつでも選ぶ |
| `group` | 欄のまとまり。`repeat` は同じまとまりを書ける数（医療機関は3件まで、など） |

`detail: true` の欄には、選んだ理由を書く詳細の欄が付きます。

## 医療の欄

病名、医療的処置のような医療の欄には `medical: true` の印があります。ツインは医療の欄も検討の材料にし、資料を読む処理も医療の情報を書かれたとおりに項目にします（`app/professional_records.py`）。しないのは、病気の診断と服薬の指示だけです（CLAUDE.md の原則17）。
